# Servo / Stylo — Lessons for Buiy

## Top of file: the single most important finding

**Servo is not the "own-layout" counterexample the brief assumed — it is the closest *Rust* validation of Buiy's exact substrate, and its `display_list/stacking_context.rs` is the single best reference implementation for Buiy's NEXT sub-pass 6f (Phase 9 stacking + top-layer).** Servo independently arrived at *Stylo for style + Taffy for flex/grid box layout* (via the `stylo_taffy` adapter), and the downstream Blitz project arrived at *Stylo + Taffy + Parley + Vello* — two production-grade Rust engines that pair the same two crates Buiy commits to. Servo's layout then computes paint order exactly the way Buiy's sub-pass 6f must: it builds a `StackingContextTree`, calls `StackingContext::sort()` by `z_index`, buckets paint phases (CSS 2.1 Appendix E), and hands the **pre-sorted tree to WebRender, which paints in order and never re-sorts** — Buiy's "layout writes, render reads" contract, already shipping in another Rust engine. The Phase 9 author should read [layout.md](layout.md) §5 against `../../specs/2026-05-08-buiy-layout-design/stacking-and-top-layer.md` §"stacking-context formation" and "paint order." The one thing Servo cannot teach is `TopLayer` — Servo has no `popover`/`::backdrop`/dialog top-layer story; for that, go to `../blink/stacking-and-paint.md`.

## Validates

Buiy choices this system confirms — each with the Servo evidence and the Buiy mechanism it backs.

- **Taffy as the box-layout substrate.** Servo embeds Taffy for *both* flexbox and CSS grid (`components/layout/taffy/`, the `stylo_taffy` crate); Blitz uses Taffy for all box layout. Two engines independently chose Taffy. This backs Buiy's `TaffyCompute` pass and the whole Taffy-bridge model in `../../specs/2026-05-08-buiy-layout-design/architecture.md` §1. (See [layout.md](layout.md) §1, [comparisons.md](comparisons.md) §5.)
- **Building *above* Taffy rather than forking it.** Servo keeps Taffy as a leaf algorithm and owns the surrounding box tree; Buiy keeps Taffy as the whole-tree solver and layers `PostTaffyOverrides` above it. Both treat Taffy as a fixed dependency, not a fork. ([layout.md](layout.md) §1; [critiques.md](critiques.md) §3.)
- **Skipping the CSS cascade.** Stylo's rule tree, style-sharing cache, and Bloom-filter ancestor matching all exist to make *string-CSS selector matching* fast. Buiy's decomposed, public-fielded ECS components erase that whole problem class — no specificity sort, no selector match, no `!important` resolution at runtime. Stylo is *inverted* prior art: it shows precisely how much machinery a real cascade costs, justifying Buiy's `SyncStyles` reading typed components instead. ([stylo.md](stylo.md) "The four mechanisms"; [stylo.md](stylo.md) "Implications for Buiy".)
- **Decomposed resolved-style structs, not a megastruct.** Stylo's `ComputedValues` groups properties into reference-counted "style structs" (`Font`, `Background`, `Position`) so only the changed slice is recomputed and the rest is shared by pointer. Buiy's equivalent is the *set* of decomposed ECS components an entity carries (no megacomponents), with Bevy change-detection giving the same "only the changed slice re-runs" property for free. ([stylo.md](stylo.md) "ComputedValues and the crate split".)
- **Layout writes, render reads (the handoff contract).** Servo's style→layout→display-list pipeline is strictly one-directional; WebRender never re-derives layout or stacking. This is exactly Buiy's contract: Phase 8 sub-pass 6e writes a private `ResolvedTransform`, Phase 9 sub-pass 6f writes a private `StackingContext { painters_z }`, and render only reads them. ([architecture.md](architecture.md) "The split that matters"; [rendering.md](rendering.md) "Why this is the model".)
- **Model the spec's data structures, not a convenient approximation.** Servo's layout-2013→2020 rewrite separated the box tree from the fragment tree because the old single "flow tree" conflated boxes with their fragments — structurally awkward for fragmentation/multicol. Buiy gets box-vs-result separation for free: Taffy owns box layout, `PostTaffyOverrides` writes a *separate* resolved-layout layer. ([architecture.md](architecture.md) "The layout-2013 → current-layout rewrite"; [critiques.md](critiques.md) §3.)
- **Parallel style in safe Rust is proven at scale.** Stylo's `rayon` work-stealing parallel cascade shipped to hundreds of millions of users in Firefox 57. Buiy's `SyncStyles`/`PostTaffyOverrides` running in Bevy's parallel ECS schedule is not a research gamble. ([stylo.md](stylo.md) mechanism 1; [open-problems.md](open-problems.md) §3.)
- **Inline and table are not Taffy's job.** Servo writes its *own* inline formatting context (`flow/inline/`: text runs, line breaker, bidi) and its *own* table FC because Taffy has neither. This confirms Buiy handling text via `cosmic-text` as measured leaves, and tables as a post-Taffy sub-pass (6b stub), rather than expecting Taffy to grow them. ([layout.md](layout.md) §4, §6; [open-problems.md](open-problems.md) §2.)
- **Bounded scope + reuse is the survival strategy.** A ~5-engineer team treats most of CSS as perpetually incomplete; Servo's value was realized by *extracting components* (Stylo, WebRender) into a fully-staffed host (Gecko), not by shipping the monolith. Buiy's bounded typed-subset + reuse-Taffy/`cosmic-text`/AccessKit/wgpu is the same hedge — and Buiy's "be useful inside Bevy" is the same "components outlive engines when they enter a host product" lesson. ([critiques.md](critiques.md) §2, §4; [governance.md](governance.md); [history.md](history.md).)
- **Accessibility must be designed in, not deferred.** Servo's a11y is thin precisely because it was deferred. Buiy's AccessKit-first, WCAG 2.2 AA floor (`../../specs/2026-05-07-buiy-foundation/accessibility.md`) is the corrective; Servo demonstrates the failure mode to avoid. ([open-problems.md](open-problems.md) §5.)

## Avoid

| Pitfall | Source | Buiy mitigation |
|---|---|---|
| **Vendoring MPL-2.0 source into a permissive tree.** Stylo/Servo/WebRender are MPL-2.0; modifications to MPL files must stay MPL and be disclosed — incompatible with Buiy's MIT/Apache crates. | [governance.md](governance.md) "License"; [critiques.md](critiques.md) §5 | Read and cite Stylo/Servo algorithms (algorithms aren't copyrightable); never copy code. Keep every load-bearing dependency MIT/Apache-compatible. Implement the typed-CSS subset yourself. |
| **Depending on `stylo` for style.** `stylo` 0.17.0 / `selectors` 0.38.0 are pre-1.0, version-churn heavily, track *Gecko's* needs first, have *no* stability guarantee, and are MPL-2.0. | [open-problems.md](open-problems.md) §4; [stylo.md](stylo.md) "crate split" | Author decomposed typed-Rust style components; reuse only MIT/Apache deps (`taffy`, `cosmic-text`). The Stylo dependency Buiy *could* take (via Blitz's `blitz-dom`) is the one Buiy declines. |
| **Chasing parallel layout.** Servo's founding "parallel layout because Rust makes it safe" thesis was part of why layout-2013 was thrown away; "lay out the whole page in parallel" is far harder than matching CSS semantics (parent sizes constrain children; floats/margins couple siblings). | [open-problems.md](open-problems.md) §3; [critiques.md](critiques.md) §3 | Buiy's layout is a deterministic *ordered* system sequence (`RemovedNodesGc`→…→`WriteResolvedLayout`); it does NOT parallelize the layout solve, leaning on Bevy's ECS scheduler for system-level parallelism elsewhere. Parallel *style* is the win; parallel *layout* is not. |
| **Letting render recompute stacking / paint order.** If paint order is re-derived in the renderer, the layout-writes/render-reads contract breaks and effects-boundary handling drifts from layout's view. | [layout.md](layout.md) §5; [rendering.md](rendering.md) "effects force off-screen passes" | Sub-pass 6f computes the *complete* sorted order into private `StackingContext { painters_z: Vec<Entity> }`; render walks `painters_z` and never sorts. Mirror Servo's `sort()`-then-`build_display_list`. |
| **A single-funder / single-steward dependency without a fork plan.** Mozilla zeroed Servo's paid engineering in one day (2020-08-11); ~2 dormant years followed. Custody (Linux Foundation) preserved IP but did not fund engineers. | [governance.md](governance.md) "bus-factor"; [history.md](history.md) 2020 entries | For each load-bearing crate (`taffy`, `cosmic-text`, `accesskit`, `wgpu`) keep a fork/vendored-snapshot contingency; tie Buiy's survival to *usefulness inside Bevy*, not to one upstream's health. (`../taffy/` notes Taffy's own single-maintainer bus-factor.) |
| **Treating "Servo supports X" as parity.** Servo does not pass full WPT; coverage is partial and person-decades behind Blink/Gecko. Presence ≠ degree. | [open-problems.md](open-problems.md) §1; [critiques.md](critiques.md) §1 | When using Servo source to settle an underspecified CSS edge, verify the *degree* of support and cross-check Blink (`../blink/`) as canonical ground truth. |
| **Expecting Servo to teach top-layer.** Servo ships no `popover`/dialog/`::backdrop` top-layer ordering comparable to Buiy's `TopLayer`. Treating Servo as the reference here yields nothing. | [layout.md](layout.md) §5 ("Servo does **not** ship a CSS top-layer story") | For `TopLayer { None\|Modal\|Popover\|Tooltip\|Fullscreen }`, the `TopLayerActivation` VecDeque, and top-layer escaping ancestor overflow clip, use `../blink/stacking-and-paint.md` as the reference, not Servo. |
| **Half-implementing the hard formatting contexts.** Inline, fragmentation/pagination/multicol, and tables are where Servo has spent *years* iterating (issue #22397 still open). | [open-problems.md](open-problems.md) §2 | Buiy keeps tables (6b) and multicol (6c) as *explicit stubs* in `PostTaffyOverrides` — honestly unsolved, not half-built — and treats shaped text as `cosmic-text` leaves rather than building an in-engine IFC. |

## Borrow

Concrete primitives worth studying (read-only; MPL-2.0 — do not copy code).

1. **`StackingContextTree` + `StackingContext::sort()` (Servo `display_list/stacking_context.rs`).** The direct reference for sub-pass 6f. Study the four child lists (`real_stacking_contexts_and_positioned_stacking_containers`, `float_stacking_containers`, `atomic_inline_stacking_containers`, `contents`) and how `sort()` orders them. **Key tiebreak finding:** `sort()` uses **`sort_by_key`** (a *stable* sort), so **equal-z-index siblings keep document order** — Servo gets CSS's tree-order tiebreak for free by building the list in document order then stable-sorting on z. Buiy's `painters_z` must do the same (`sort_by_key`, *not* `sort_unstable_by_key`) or the equal-z order is nondeterministic. (See [layout.md](layout.md) §5 "Sort stability / z-index ties".)
2. **`StackingContextSection` buckets vs CSS 2.1 Appendix E's ~7 steps.** The enum has only *four* variants (`OwnBackgroundsAndBorders`, `DescendantBackgroundsAndBorders`, `Foreground`, `Outline`), yet Appendix E defines ~7 paint phases. The reconciliation: the full order is the *cross-product* of (which child list) × (which z-slice of the z-sorted context list: negative / z:0-auto / positive) × (which section bucket) — the enum names only the within-box phases; the document-order/z interleave lives in the list splits. Buiy's `painters_z` collapses that cross-product into one flat `Vec<Entity>`. Do not assume "4 buckets" means "4 steps." (See [layout.md](layout.md) §5 "How 4 section buckets + 4 child lists reconstruct…".)
3. **Stacking-context *formation* triggers read off `ComputedValues` — and the Phase 8 → 9 transform seam.** Servo's `establishes_stacking_context(flags)` returns true for non-empty `filter`, `opacity != 1.0`, `mix-blend-mode`, an active `transform` *or* `perspective` (`has_effective_transform_or_perspective()`), `clip-path`, `transform-style != Flat`, plus positioned+z-index, `isolation: isolate`, `contain: paint`, and root — the same **union of triggers** Buiy's Phase 9 spec defines. Critically, this is the **seam with Phase 8**: a non-identity `ResolvedTransform` (6e, landed) is *both* a transform reference frame *and* a stacking-context former, so 6f must treat transformed entities as formers (cannot read transform state independently of 6e). It is *also* where `position: fixed` re-parents: Servo's `for_absolute_and_fixed_descendants` updates the fixed containing block to a transformed ancestor — Buiy must apply the same CSS rule or a fixed element's position and stacking membership diverge. (See [layout.md](layout.md) §5 "The Phase 8 → Phase 9 seam" and "Fixed-position containing block under transforms".)
4. **The display-list / retained-scene / batching split (WebRender).** The model for Buiy's render handoff: a flat, *unrasterized* list of primitives with clips/transforms/stacking contexts, a retained scene rebuilt only where it changed (Buiy gets this from Bevy change-detection), and a frame builder that culls + batches. Study which constructs force *off-screen passes* (opacity-over-a-group, `filter`, `mix-blend-mode`, non-rect clips) — these are the *same* triggers that form a stacking context, so sub-pass 6f's group boundaries hand render exactly the grouping it needs.
5. **`stylo_taffy` adapter (`TaffyStyloStyle`).** The pattern for turning a typed style representation into Taffy's style traits without forking Taffy. Buiy's `Style`-builder→Taffy bridge solves the same adapter problem; the `stylo_taffy` crate (MPL-2.0, now vendored in Blitz) is a reference for the trait-mapping surface.
6. **The box-tree / fragment-tree two-level model (`components/layout/fragment_tree/`).** `BoxFragment`, `PositioningFragment`, `ContainingBlock`, `FragmentTree` — one box producing many fragments. The lesson, not the code: keep the layout *inputs* immutable and produce an immutable *result* layer. Buiy's `WriteResolvedLayout` writing a separate resolved layer is the same discipline.
7. **Stylo's structural-sharing trio (rule tree / style-sharing cache / Bloom filter).** Study as *inverted* prior art — to understand the cost of the cascade Buiy is right to skip. The one transferable fragment: the Bloom-filter-as-sound-fast-reject pattern, worth keeping in mind if Buiy's container-query ancestor walk (`CqActivate`) ever shows up in a profile.
8. **`unicode-bidi` (Servo-authored, reusable).** The UAX #9 bidi crate the broader Rust ecosystem reuses. Buiy's text is `cosmic-text`, which handles bidi, but `unicode-bidi` is a permissively-usable reference for the algorithm Servo's IFC depends on. (Verify its license before depending — it is separate from Servo's MPL tree.)

## How to use this file

- **Phase 9 plan author (sub-pass 6f, the NEXT work):** read "Top of file," then "Borrow" items 1–4, then the "Avoid" rows on render-recompute and top-layer. Cross-read [layout.md](layout.md) §5 and `../blink/stacking-and-paint.md` (Blink is the top-layer reference Servo lacks). Map `StackingContext::sort()` order onto `painters_z`; map the union-of-triggers onto `Stacking` formation.
- **Substrate / dependency reviewer:** read "Validates" (Taffy, above-Taffy, skip-the-cascade) and the "Avoid" rows on MPL vendoring, depending on `stylo`, and single-funder risk. Cross-read [governance.md](governance.md) and [comparisons.md](comparisons.md) §5 (Blitz).
- **Scope / planning author:** read "Validates" (bounded scope + reuse) and [critiques.md](critiques.md) §2 + [open-problems.md](open-problems.md) §1–2 for which CSS corners are genuinely hard.
- Always treat Servo source as **reading reference only** (MPL-2.0). Borrow ideas; verify CSS *degree* against Blink (`../blink/`).
