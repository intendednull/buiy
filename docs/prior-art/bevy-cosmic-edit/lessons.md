# Lessons for Buiy

This is the consult-this-when-designing file. Other files in this folder are evidence; this is synthesis. When designing any Buiy feature touching the text-edit surface — `buiy-text-editing-design` (eventual sub-spec), focus model, IME boundary, render-to-texture rejection, undo/redo — start here.

## The headline

**bevy_cosmic_edit's archive on 2025-03-21 is the canonical validation of Buiy's text-edit ownership commitment.** Where most prior-art lessons.md files have a long Validates / long Borrow / shorter Avoid mix, this one is the inverse: the entire architectural shape of the crate is a "don't reproduce this" pattern; the borrowable bits are narrow primitives, not architecture. Read [`why-archived.md`](why-archived.md) before anything else in this folder.

## Validates

These Buiy design choices are confirmed by bevy_cosmic_edit's failure trajectory:

- **Buiy owns its text-edit surface end-to-end** (foundation [text.md § 3.5](../../specs/2026-05-07-buiy-foundation/text.md#35-text-editing)). bevy_cosmic_edit demonstrates that a third-party crate trying to span "cosmic-text on one side, bevy_ui on the other" is structurally fragile. Both sides are fast-moving Rust UI ecosystems with independent breaking-release cadences; the bridge maintenance burden compounds. See [`why-archived.md`](why-archived.md).
- **Buiy does not depend on `bevy_cosmic_edit`** (cemented in [`../cosmic-text/lessons.md`](../cosmic-text/lessons.md) row "Depending on `bevy_cosmic_edit`"). The crate is archived; the most-recent compat is Bevy 0.15; no fork is canonical. Treating it as a current dependency would inherit ~21 months of unfixable architectural mismatch.
- **Buiy integrates cosmic-text directly, not via bevy_text** (foundation [`architecture.md` § 2.3](../../specs/2026-05-07-buiy-foundation/architecture.md)). bevy_cosmic_edit's drift from explicit-cosmic-text-pin to riding-bevy_text's-transitive-version was a load-bearing decay path. When bevy_text migrated off cosmic-text (issue [#21765](https://github.com/bevyengine/bevy/issues/21765)), bevy_cosmic_edit had no upgrade path. Buiy's direct integration is the structural counter-pattern.
- **Buiy implements preedit IME rendering as a Foundation requirement** (foundation [`text.md` § IME composition](../../specs/2026-05-07-buiy-foundation/text.md#34-typography)). bevy_cosmic_edit's "no preedit, commit-only" was a visible production gap; Buiy's "preedit underline / highlight / cursor positioning, F-tier" is the response.
- **Buiy commits to a render-graph-integrated text pipeline, not render-to-texture** (foundation `architecture.md` § 2.3 "What Buiy owns"). bevy_cosmic_edit's per-buffer CPU `RgbaImage` re-upload was unscalable past small inputs; per-keystroke whole-image upload is the design choice Buiy explicitly avoids.
- **Buiy plans a real focus tree, not a `FocusedWidget` singleton** (foundation `architecture.md` § 2.3 § "What Buiy owns"; foundation `interaction.md` § 3.7). `bevy_cosmic_edit::FocusedWidget` was a `Resource<Option<Entity>>` — single global focus, no stack, no traps, no restoration, no inert subtrees. Buiy's focus tree with `:focus-visible` semantics, traps, restoration, inert, roving tabindex, sequential-focus-navigation-starting-point, spatial gamepad nav is the response.
- **Buiy commits to undo / redo with composition-aware grouping** (foundation [`text.md` § Editing operations](../../specs/2026-05-07-buiy-foundation/text.md#35-text-editing)). bevy_cosmic_edit *removed* undo/redo in 0.17 to shrink the maintenance surface — a visible signal of bridge-crate scope retreat. Buiy treats it as **F**oundation tier.
- **Buiy ships event-rich text-edit** (foundation `interaction.md` for event taxonomy). bevy_cosmic_edit's one-event API (`CosmicTextChanged`) forced consumers to poll-and-diff. Buiy's text-edit publishes `CursorMoved`, `SelectionChanged`, `CompositionStart/Update/End`, `EditCommitted`, `EditCancelled`, `FocusGained/Lost` as first-class observable events.

## Borrow

Despite the architectural mismatch at the crate level, several **narrow primitives** in bevy_cosmic_edit's shape are worth studying for Buiy's text-edit work. Borrow these patterns; don't borrow the crate.

1. **The `EditorBuffer` `QueryData` pattern.** A Bevy ECS `QueryData` struct wrapping (optional editor) + (required buffer) — `editor: Option<&'static mut CosmicEditor>, buffer: &'static mut CosmicEditBuffer` — lets read-only entities (without `CosmicEditor`) and editable entities (with) share the same query path. The `EditorBufferItem`'s `Deref<Target = Buffer>` makes it ergonomic. Buiy's eventual text component should consider this shape: the editor-optional / buffer-required separation is genuinely clean. See [`architecture.md` § The Editor / Buffer split](architecture.md#the-editor--buffer-split--borrowed-from-cosmic-text).
2. **Decomposed style components.** Even at archive, bevy_cosmic_edit had `CursorColor`, `SelectionColor`, `SelectedTextColor`, `CosmicBackgroundColor`, `DefaultAttrs`, `CosmicWrap`, `CosmicTextAlign`, `MaxLines`, `MaxChars`, `ReadOnly`, `ScrollEnabled` as independent components. This is exactly the shape `bevy-ui/lessons.md` § Avoid (`AccessibilityNode` megacomponent) tells us bevy_ui got wrong elsewhere; bevy_cosmic_edit got it right by accident or design. Buiy's text-edit components should be similarly decomposed. See [`architecture.md` § Decomposed style components](architecture.md#decomposed-style-components).
3. **`ReadOnly` as a marker component.** Disabling all write paths by adding a `ReadOnly` marker component is cleaner than gating each write system on a boolean field. Buiy's text-edit `ReadOnly` and `Disabled` markers can mirror this. The same pattern likely applies to `Inert` for the focus/picking/a11y short-circuit (per the `bevy-ui/lessons.md` borrow #8).
4. **`MaxLines` + `MaxChars` as enforced-pre-`Action` limits.** Pre-input validation: before forwarding a keystroke to cosmic-text, check the count limits. Cleaner than letting cosmic-text accept the input then truncating. Buiy's text-edit can absorb this pattern when implementing `maxlength` analogs.
5. **`CosmicWrap` enum shape.** `InfiniteLine` vs `Wrap` cleanly maps to CSS `white-space: nowrap` vs the wrap default. Borrow the variant set when designing Buiy's text-component wrap surface (cosmic-text's own `Wrap::None / Glyph / Word / WordOrGlyph` is the underlying enum and what Buiy ultimately uses — see [`../cosmic-text/lessons.md`](../cosmic-text/lessons.md) borrow #3).
6. **Double-click + triple-click word/line selection as a separate concern.** `double_click.rs` and the triple-click logic were factored out of the main input system. Cleaner than inlining clicktime/clickdistance heuristics into the main mouse handler. Buiy's text-edit can mirror the separation.
7. **The `focus_on_click()` helper as opt-in convenience.** Rather than auto-focus-on-click in the plugin, bevy_cosmic_edit exposed `focus_on_click()` as a system the consumer added if they wanted that behavior. This is the right knob — focus behavior is policy, not mechanism. Buiy's focus tree should expose focus-on-click as opt-in policy too.
8. **Sub-plugins for opt-in features.** `PlaceholderPlugin`, `PasswordPlugin`, `UserSelectPlugin` were separate plugins consumers added if they wanted those behaviors. Aligns with Buiy's "small components, opt-in subsystems" stance. (Caveat: this was also a maintenance-shrinking move per 0.17 CHANGELOG; the *strategic* shape is good even if the *trigger* was burden-management.)
9. **`internal-debugging` feature gating `bevy/track_change_detection`.** A maintainer-only feature flag for change-detection tracking. Useful pattern for a Buiy-internal debugging feature surface.
10. **`bevy_picking` integration as a render-target-neutral entry.** PR #167 (2024-12-12) made hit-testing flow through `bevy_picking` so the same editor entity could be queried-via-picking regardless of being a `Sprite` or `ImageNode`. Same idiom in Buiy: text-edit components register a `bevy_picking` backend so pointer events route uniformly. See [`../bevy-picking/README.md`](../bevy-picking/README.md).

## The structural lesson, restated

**The biggest single thing this folder teaches:** a third-party Rust crate maintaining hand-rolled compatibility with two fast-moving upstream UI ecosystems has no sustainable equilibrium without funded stewardship or a stable upstream API. bevy_cosmic_edit had neither; it got 21 months of value out and then was archived. The reproduction strategy for Buiy is: own the seam. Make text-edit a *first-class* Buiy concern, not a *third-party-plugin* concern. The maintenance burden becomes "track Bevy + cosmic-text" — which is the same load Buiy already accepts as its core mandate; no additional bridge layer to fund.

Other Buiy specs touching text-edit, focus, IME, undo/redo, render pipeline, render-graph integration — please read [`why-archived.md`](why-archived.md) before committing to any architectural shape that resembles bevy_cosmic_edit's.

1. **Find the row in Avoid** that names a pitfall close to your design. Read the linked file for the evidence. Apply the mitigation.

3. **Promote any decision into a Buiy spec under `docs/specs/`.** This file is for capturing what we learn from bevy_cosmic_edit's archive; it is not where Buiy decisions live.
