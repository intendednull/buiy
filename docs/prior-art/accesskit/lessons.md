**Subject:** AccessKit — lessons for Buiy: which design choices it validates, which pitfalls to avoid, which primitives to borrow

# Lessons for Buiy

This is the consult-this-when-designing file. The other prior-art files are evidence; this file is decisions. AccessKit is **load-bearing for Buiy's accessibility story** — Buiy is the producer, AccessKit is the bridge, the platform AT is the end consumer. Most Buiy a11y decisions reduce to "how does this map onto AccessKit's contract?" — this file enumerates the answers.

## Validates

These Buiy design choices are confirmed by AccessKit's experience and API shape:

- **AccessKit-first, talk-to-`accesskit_winit`-directly.** Building `TreeUpdate`s directly with decomposed components is the right primitive — far cleaner than retrofitting `bevy_a11y`'s megacomponent `AccessibilityNode(NodeBuilder)` shape onto BSN's "small, public-fielded, observable, decomposed" requirement. Bevy issue [#17644](https://github.com/bevyengine/bevy/issues/17644) names the problem; Buiy's `A11yRole` / `A11yLabel` / `A11yDescription` / `A11yStates` / `A11yRelations` split is the prescribed fix. See [`integration.md`](integration.md) and [`api.md`](api.md).
- **Per-window adapter ownership keyed by winit `WindowId`.** AccessKit's one-tree-per-`accesskit_winit::Adapter`-per-window model is structural — there is no upstream API to attach two adapters to one window. Buiy's per-window keying ([`cross-cutting.md § 3.18`](../../specs/2026-05-07-buiy-foundation/cross-cutting.md)) matches AccessKit's shape exactly. The same constraint is why Buiy *cannot* coexist with `bevy_a11y` on the same window — there's nothing to coexist *with*; the adapter slot is single-occupant. See [`platform-adapters.md`](platform-adapters.md), [`integration.md`](integration.md).
- **Lazy-tree-build gating via `AccessibilityRequested`.** AccessKit's `update_if_active` runs the closure only when an AT is attached; idle windows pay nothing. Buiy's `BuiySet::A11yUpdate` system honors the same gate. Validates the cost-amortisation choice in [`architecture.md § 2.6`](../../specs/2026-05-07-buiy-foundation/architecture.md). See [`architecture.md`](architecture.md).
- **Decomposed components map cleanly onto AccessKit's Node API.** `Node::new(Role)` + ~200 setter methods means there is no megacomponent in the AccessKit API to mirror — every property is reachable independently. The producer-side lesson is that the BSN-hostility came from `bevy_a11y`'s wrapper, not from AccessKit itself. See [`api.md`](api.md), [`tree-model.md`](tree-model.md).
- **ACCNAME 1.2 implementation in `buiy_core`, not pulled from AccessKit.** AccessKit deliberately does not compute accessible names — it holds the references (`set_labelled_by`, `set_described_by`, `set_label`, `set_description`) and trusts the consuming toolkit to walk them per ACCNAME 1.2. The Buiy spec moves the algorithm into `buiy_core`. Confirmed by [`capabilities.md`](capabilities.md) and [`ecosystem.md`](ecosystem.md).
- **Replace-`bevy_a11y`-per-window posture, not layer over.** AccessKit's adapter-slot-is-single-occupant rule makes layering impossible. The Buiy spec's "Buiy suppresses `bevy_a11y` on Buiy-owned windows" rule ([`cross-cutting.md § 3.18`](../../specs/2026-05-07-buiy-foundation/cross-cutting.md)) is the only design AccessKit's shape allows.
- **Cross-platform tree shape as the contract.** Buiy writes `Node` + `Action` + relation once and the adapters distribute it to UIA / NSAccessibility / AT-SPI / Android / iOS. Buiy gets correct AT behavior on every supported platform without per-platform conditionals in producer code. See [`architecture.md`](architecture.md), [`ecosystem.md`](ecosystem.md).
- **Stable `NodeId`s derived from Bevy `Entity` (via `Entity::to_bits()`).** AccessKit treats `NodeId` as an opaque `u64`; the producer chooses the value space. Entity-to-bits gives stable identity across frames and matches AccessKit's diff-model expectation. See [`api.md`](api.md).
- **AccessKit's `Tree.focus: NodeId` as the authoritative focus signal.** One focused node per tree per update — exactly matches Buiy's "single focus model with `:focus-visible` semantics" design.
- **`TreeUpdate` delta protocol — push diffs, not full trees.** AccessKit's "full initial then diff thereafter" matches Buiy's ECS change-detection-driven update path. The activation handler returns the full tree; subsequent frames push only changed nodes. See [`architecture.md`](architecture.md).
- **Multi-window app support.** AccessKit supports one adapter per window cleanly, with per-tree `NodeId` scoping (no global collision). Buiy's multi-window story inherits this directly. See [`integration.md`](integration.md), [`critiques.md` O9](critiques.md).

## Avoid

| Pitfall | Source | Buiy mitigation |
|---|---|---|
| Using stale `NodeBuilder` / `NodeClass` API in examples or docs | [`api.md`](api.md) — API changed before 0.24 line | Use direct `Node::new(role)` + setters. Verify against live `accesskit` 0.24.0 docs.rs before lifting any code sample. External tutorials predating ~2025-Q4 likely show the wrong shape. |
| Spelling `labeled_by` (American) instead of `labelled_by` (British) | [`tree-model.md`](tree-model.md), [`api.md`](api.md) | The AccessKit field name is `labelled_by`. Buiy's component / API surface doesn't have to match (Buiy can name its component `A11yRelations::labelled_by` or `labeled_by` either way), but the call to AccessKit's setter MUST use the British spelling — and the Buiy field name should follow to avoid translation mistakes. |
| Treating `is_focused` as a node-state field | [`tree-model.md`](tree-model.md), [`api.md`](api.md) | Focus is `TreeUpdate.focus: NodeId` — one focused node per tree per update, set on every update (repeat the previous frame's id if unchanged). Buiy's focus model maps to this, not to a per-node bool. |
| Using `bool` instead of `Option<bool>` for Selected / Expanded | [`tree-model.md`](tree-model.md) | `Selected` and `Expanded` are tri-state in ARIA (`true` / `false` / not-applicable). `is_selected -> Option<bool>` and `is_expanded -> Option<bool>` on AccessKit's `Node`. Buiy's components must encode the three states or risk mis-emitting "not applicable" as "false". |
| Using `bool` instead of the `Toggled` enum for checked/pressed | [`tree-model.md`](tree-model.md), [`capabilities.md`](capabilities.md) | `Toggled { False, True, Mixed }` unifies `aria-checked` and `aria-pressed`. `Mixed` matters for tri-state checkboxes and partially-applied "pressed" states (the "select-all-with-some-children-selected" UI). Buiy's checkbox / toggle widgets emit `Toggled`, not `bool`. |
| Using `bool` instead of the `Invalid` enum for validation state | [`tree-model.md`](tree-model.md) | `Invalid { False, True, Grammar, Spelling }`. Buiy's form-validation state machine must distinguish these — `Grammar` and `Spelling` get different AT verbalisations than generic `True`. |
| Coupling tests / fixtures to a specific AT (NVDA / VoiceOver / TalkBack) utterance | [`critiques.md` §1, §7, §8](critiques.md), [`ecosystem.md`](ecosystem.md) | Test against the AccessKit `Tree` and `Node` property names — not against AT verbalisations. Utterances drift across AT versions, language packs, and verbosity settings. Buiy's verification harness snapshots the tree; real-AT cross-checking is a manual release gate, not a CI gate ([`verification.md`](../../specs/2026-05-07-buiy-foundation/verification.md)). |
| Counting on Iced, Tauri, or GPUI as evidence of AccessKit adoption | [`ecosystem.md`](ecosystem.md) — verified false / partial | Cite **only verified** adopters: egui (production, enabled by default in eframe), Slint (production), Freya (production), Bevy via `bevy_a11y` (production), Xilem/Masonry (production). Tauri uses WebView a11y; GPUI/Zed has no AccessKit; Druid is discontinued; Iced has draft PRs only. Don't over-claim adoption breadth. |
| Confusing producer / consumer terminology | [`README.md`](README.md), [`platform-adapters.md`](platform-adapters.md), [`api.md`](api.md) | Buiy is the **producer**. `accesskit_consumer` is the adapter-side library — for adapter authors, not application authors. Application code never depends on `accesskit_consumer`. The end-consumer of accessibility information is the AT (NVDA / VoiceOver / …), reached only through the OS adapter. Spec authors who slip into "Buiy consumes AccessKit" will get the bug-report routing wrong. |
| Treating any platform adapter as bug-free | [`platform-adapters.md`](platform-adapters.md) — issue #520 macOS ListBox selected state | Pre-1.0 means real bugs. macOS issue #520 is the named one as of folder-write; others will appear. Coordinate via the Buiy verification harness manual-release-gate; ship platform-specific expect-failure fixtures when known bugs land. |
| Releasing Buiy v1 with iOS or Android in CI | [`platform-adapters.md`](platform-adapters.md), [`accessibility.md`](../../specs/2026-05-07-buiy-foundation/accessibility.md) | Per Buiy's foundation spec, mobile is manual-release-gate only. `accesskit_ios` 0.1.0 is 11 days old at folder-write; `accesskit_android` 0.7.3 is pre-1.0. Revisit when each adapter exposes a headless harness usable in CI. |
| Counting on the web adapter for v1 | [`platform-adapters.md`](platform-adapters.md), [`history.md`](history.md), [`critiques.md` §3, O2](critiques.md) | No `accesskit_web` crate exists on crates.io. No active WIP PR visible. The web case is architecturally different (DOM-aligned ARIA, not parallel tree). Bevy WASM target is partial-a11y until upstream ships. Don't promise web accessibility in v1; document the gap. |
| Forgetting coordinate-space conversion | [`architecture.md`](architecture.md), [`tree-model.md`](tree-model.md), [`integration.md`](integration.md) | `Node::set_bounds` takes window-relative logical pixels; the adapter applies window position + DPI scale to produce screen coords. Producers should not bake screen position into the tree — that would invalidate every node on every window move. Buiy reads computed layout rects in window-local logical coords directly. |
| Cross-thread `update_if_active` call | [`api.md`](api.md), [`integration.md`](integration.md) | The adapter must be called on the winit window thread (the event-loop thread; the main thread on macOS). AccessKit data types are `Send + Sync` so you can build them on any thread, but the call into `Adapter::update_if_active` is single-threaded. Buiy's a11y system runs in the main schedule, not a parallel system. |
| Not gating on `AccessibilityRequested` | [`architecture.md`](architecture.md) | Building a 500-node `TreeUpdate` per frame for an idle window is real cost — pay it only when an AT is listening. `accesskit_winit`'s activation event flows into Buiy's `AccessibilityRequested` resource; `BuiySet::A11yUpdate` short-circuits when it's not set. |
| Misattributing AccessKit lineage to NVDA | [`history.md`](history.md), [`governance.md`](governance.md) | Matt Campbell is co-founder + CTO of Pneuma Solutions (founded 2020 with Mike Calvo) and was previously at Serotek Corporation + Microsoft Windows Accessibility Team. NVDA was created by Michael Curran (2006), co-led by James Teh — separate lineage. Don't confuse the lineages in any Buiy doc, blog post, or PR description; it's been repeatedly miscited and a future external reviewer will catch it. |
| Coupling to a specific AccessKit minor version across Bevy migrations | [`accessibility.md`](../../specs/2026-05-07-buiy-foundation/accessibility.md), [`architecture.md § 2.9`](../../specs/2026-05-07-buiy-foundation/architecture.md), [`critiques.md` §6](critiques.md), [`governance.md`](governance.md) | AccessKit releases on its own irregular cadence (six-month gap mid-2025, three releases in three weeks early 2026, ten co-released crates 2026-05-11). Minor bumps regularly carry breaking changes; the entire crate set co-releases. Buiy commits to the AccessKit cadence even when it diverges from Bevy's: "AccessKit major release between Bevy minors triggers a Buiy patch release" — and read "minor or major" given pre-1.0 versioning. Document in Buiy's load-bearing-dep contingencies. |
| Hand-spelling `aria-relevant` semantics via AccessKit | [`tree-model.md`](tree-model.md) | AccessKit's node model carries `Live` + `is_live_atomic` but NOT `aria-relevant`. Buiy must layer the `additions / removals / text / all` filtering on its own side — deciding which mutations warrant a TreeUpdate-and-announcement vs. silent updates. The global announcer service ([`accessibility.md` "Live regions and announcements"](../../specs/2026-05-07-buiy-foundation/accessibility.md)) owns this. |
| Treating the `Role` enum as extensible | [`capabilities.md`](capabilities.md), [`critiques.md` O8](critiques.md) | `Role` is `#[repr(u8)]` and **closed**. Custom widget patterns that don't fit one of the 182 variants fall back to `Role::Generic` + `set_role_description(str)`. New ARIA roles (1.3 drafts, future additions) wait for an AccessKit bump. Don't design Buiy widgets that assume a role AccessKit doesn't yet have. |
| Pushing rich-text / hypertext through AccessKit as structured runs | [`tree-model.md`](tree-model.md), [`capabilities.md`](capabilities.md), [`critiques.md` §9](critiques.md) | Per upstream README: rich text / hypertext is not modeled. Multi-run cosmic-text paragraphs flatten to a single `value` string on the containing node; structure conveyed only via parent/child tree shape (`Paragraph` → `Heading` / `Emphasis` / `Strong` children). The text-editor widget contract must inherit this limitation. |
| Assuming AT-SPI behaves identically on X11 and Wayland | [`platform-adapters.md`](platform-adapters.md), [`critiques.md` O4](critiques.md) | Wayland intentionally hides absolute window positions (sandbox); `winit::Window::inner_position()` returns `Err` on most Wayland desktops. Bounds reported to AT-SPI may be wrong / relative. Buiy verifies on BOTH session types and documents the divergence — this is an open question in [`architecture.md § 2.9`](../../specs/2026-05-07-buiy-foundation/architecture.md). |
| Trusting `accesskit_winit::Adapter::new` on a visible window | [`api.md`](api.md), [`platform-adapters.md`](platform-adapters.md) | All three adapter constructors **panic** if the window is already visible — by design, to make the AT detect a11y info on first show. Buiy must register the adapter in the window-creation flow, before the window appears. |
| Forgetting the Unix async-runtime feature flag | [`api.md`](api.md), [`platform-adapters.md`](platform-adapters.md) | On Linux, `accesskit_unix` is async-runtime-backed (D-Bus); `accesskit_winit` propagates the requirement — the producer must enable `tokio` or `async-io` on `accesskit_winit`. Buiy uses `async-io` (lighter dependency closure). Open question worth pinning in a sub-spec. |

## Borrow

Concrete subsystems and patterns worth deep study (and direct adaptation where the licenses align — AccessKit is MIT OR Apache-2.0, matching Buiy's expected dual license):

1. **The `Tree` + `TreeUpdate` delta protocol.** Buiy pushes the full tree once on activation (`ActivationHandler::request_initial_tree`), then diff-style `TreeUpdate`s thereafter — every frame an accessibility-relevant entity changes, the `TreeUpdate.nodes` carries only the changed nodes. The `Tree` metadata struct (`root: NodeId`, `toolkit_name: Some("Buiy")`, `toolkit_version: Some(env!("CARGO_PKG_VERSION"))`) is `Some` only on initial activation or when toolkit metadata changes. See [`architecture.md`](architecture.md), [`api.md`](api.md).

2. **The `AccessibilityRequested` activation gate.** `Adapter::update_if_active(|| build_tree_update())` short-circuits unless an AT is attached. Buiy lifts the gate into `BuiySet::A11yUpdate` so the entire per-frame a11y system is a no-op on idle windows. See [`architecture.md`](architecture.md).

3. **`NodeId` derived from Bevy `Entity::to_bits()`.** Stable identity across frames matches AccessKit's diff-model expectation. Entity de-spawn means the NodeId vanishes, which matches AT expectations for node lifecycle. See [`api.md`](api.md).

4. **The `Role` enum (closed, 182 variants) as the contract.** Buiy maps APG widget patterns directly to AccessKit roles per [`accessibility.md` § 3.11](../../specs/2026-05-07-buiy-foundation/accessibility.md). Bespoke widgets fall back to `Role::Generic` + `set_role_description(str)`. Pin each Buiy widget's emitted Role in the widget catalog. See [`capabilities.md`](capabilities.md), [`tree-model.md`](tree-model.md).

5. **The `Action` enum (22 variants) for ATs to invoke widgets.** `Click`, `Focus`, `Blur`, `Increment`, `Decrement`, `SetValue`, `SetTextSelection`, `ScrollIntoView`, `ScrollToPoint`, `ShowContextMenu`, `CustomAction`, etc. Buiy routes incoming `ActionRequest { action, target: NodeId, data }` to the Buiy entity whose `NodeId` matches the target — via Buiy's own action plumbing, NOT `bevy_a11y`'s event bridge. Producer marks a node as supporting an action via `Node::add_action(Action::...)`. See [`tree-model.md`](tree-model.md), [`api.md`](api.md), [`integration.md`](integration.md).

6. **`Tree.focus: NodeId` as the authoritative focus signal.** Carried on every `TreeUpdate`, not via a per-node bool. Buiy's focus model derives the value from its focus tree each frame and writes it into the outgoing update. See [`tree-model.md`](tree-model.md), [`api.md`](api.md).

7. **`Toggled { False, True, Mixed }` and `Invalid { False, True, Grammar, Spelling }` tri-state enums.** Buiy's form-validation state machine and toggle / checkbox widgets adopt these directly — `bool` is wrong here. See [`tree-model.md`](tree-model.md), [`capabilities.md`](capabilities.md).

8. **The ARIA relation set: `labelled_by`, `described_by`, `controls`, `flow_to`, `owns`, `active_descendant`, `error_message`, `details`, `popup_for`, `radio_group`, `in_page_link_target`, `member_of`, `next_on_line`, `previous_on_line`.** Buiy's `A11yRelations` component exposes the same set; Buiy's spec lists the same relation names. The British double-l spelling on `labelled_by` is non-negotiable on the AccessKit-call side. See [`tree-model.md`](tree-model.md), [`capabilities.md`](capabilities.md).

9. **`Live { Off, Polite, Assertive }` + `is_live_atomic` + `is_busy` for live regions.** Buiy's live-region announcer adopts the semantics directly. `aria-relevant` is NOT in AccessKit — Buiy layers it on its own side (which mutations warrant a push) and uses AccessKit's `Live` enum for politeness only. See [`tree-model.md`](tree-model.md), [`capabilities.md`](capabilities.md).

10. **The producer / adapter protocol shape — a data protocol, not a Rust trait.** AccessKit's design keeps the producer-side language-agnostic (C and Python bindings consume the same schema). Buiy benefits indirectly: a future non-Rust consumer of the same accessibility shape can be added by binding to the same AccessKit C API. Don't blur the producer/adapter boundary with toolkit-specific traits leaking across it. See [`architecture.md`](architecture.md).

11. **`Action::SetSequentialFocusNavigationStartingPoint` as the AT entry point into the focus model.** AccessKit relays the request; Buiy's focus model implements the "Tab from here" behaviour. The `Action` is the route, not the implementation. See [`capabilities.md`](capabilities.md), [`accessibility.md`](../../specs/2026-05-07-buiy-foundation/accessibility.md).

12. **The role-description fallback pattern.** When Buiy adds a widget that doesn't fit any `Role` variant (e.g. a novel composite gesture-driven widget), emit `Role::Generic` + `set_role_description("custom name")`. The AT reads the role description aloud verbatim. This is the supported escape hatch; use it sparingly and document each occurrence in the widget catalog. See [`capabilities.md`](capabilities.md).

## How to use this file

When designing a Buiy feature that touches accessibility, first locate the relevant Avoid row and read its source file to understand the trap; then locate the relevant Borrow row to identify the AccessKit primitive your design should adopt. Promote any decision into a Buiy spec under `docs/specs/` — this file captures what we learn from AccessKit, not Buiy's own commitments. When AccessKit ships a breaking minor or a new adapter, this file's claims may drift; re-verify against the live `accesskit` docs.rs + crates.io before lifting any concrete API shape.
