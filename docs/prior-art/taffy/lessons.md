# Lessons for Buiy

This is the consult-this-when-designing file. The other prior-art files are evidence; this file is decisions. Most of Buiy's layout architecture (the bridge, the hybrid `Style` builder, the decomposed components, the 8-step pipeline, the post-Taffy sub-passes) sits on top of decisions Taffy already shipped or already deferred. The file says which Taffy choices Buiy adopts, which pitfalls Buiy has explicit mitigations for, and which primitives are worth borrowing into Buiy's own layers.

## Validates

These Buiy design choices are confirmed by Taffy's experience:

- **Hybrid `Style` builder + decomposed per-property components.** Taffy itself ships a single mega-`Style` struct (40+ fields). Embedders that want ECS-friendly storage decompose at their own layer — Bevy UI uses one `Node` mega-component; Buiy decomposes into ~15 typed components (`Display`, `LogicalBoxModel`, `FlexParams`, `GridParams`, `Overflow`, `WritingMode`, `Container`, `Anchor`, `Stacking`, `Transform`, `Containment`, `MultiColumn`, `Scroll`, `Children/ChildOf`). The `Style` builder collapses them back into one `taffy::Style` per node in `SyncStyles`. Decomposition is at the ECS layer, mega-struct is at the Taffy bridge — both stay in their lane. See [integration.md § 7](integration.md).

- **Per-frame `sync_styles` system with change detection.** Bevy UI does this; Blitz does this; Buiy does this. The pattern works: rebuild the `taffy::Style` only when one of the decomposed components carries `Changed<_>`. Skip nodes whose inputs haven't changed and Taffy's cache returns the cached `LayoutOutput`. Buiy's 8-step pipeline ([architecture.md § 3 of the Buiy spec](../../specs/2026-05-08-buiy-layout-design/architecture.md#3-system-pipeline)) is the canonical implementation. See [integration.md § 6](integration.md).

- **Const-construction discipline for static styles.** `Style::DEFAULT` is `const`; `length()`, `percent()`, `auto()`, `zero()` are `const fn`; `CompactLength` is const-constructible since 0.8. Static styles can live as `static FOO: Style = Style { ..Style::DEFAULT };` with zero runtime cost. Buiy's `Style` builder must preserve this — fluent methods are nice-to-have, but the struct-literal-into-`..Style::DEFAULT` path must compile to const. See [api.md § 6](api.md).

- **`LayoutPartialTree` / `TraversePartialTree` / `CacheTree` as a clean integration boundary.** Three separable concerns: child topology, layout dispatch, caching. Each can be implemented independently. Buiy currently wraps `TaffyTree` (Phase 0); the trait path is reserved for a future bridge that drops the `Entity → TaffyNodeId` map. The trait split makes that migration possible without redesigning the algorithm. See [architecture.md § 2](architecture.md).

- **Multi-algorithm support (Flexbox + Grid + Block + Float) in one engine.** Production-proven across Bevy 0.9+, Servo, Blitz, Zed, Lapce, Slint. This is the load-bearing reason Buiy picked Taffy over Yoga-via-bindings: Buiy needs Grid + Block + Float, Yoga is Flexbox-only. See [ecosystem.md § 2](ecosystem.md).

- **`Style` is `!Send + !Sync` since 0.8 → Buiy stores `LayoutTree` as a `NonSendResource`.** Tagged-pointer `CompactLength` carries opaque pointers; the type cannot be `Send`. This is intentional (it's what enables `calc()`'s embedder-owned evaluator) and not changing. Layout is sequential anyway, so the restriction is free. Buiy's `LayoutTree` `NonSendResource` decision is validated. See [architecture.md § 8](architecture.md).

- **`Display::None` short-circuit.** Taffy's `compute_hidden_layout` produces a zero-rect synchronously without descending into children. Buiy's `Display::None` semantics map cleanly; subtrees of hidden nodes pay no layout cost. See [layout-algorithms.md § 5](layout-algorithms.md).

- **Taffy 0.10 features Buiy specifically benefits from.** Two that landed since the Buiy layout spec was drafted:
  - **`Float` + `Clear`** (feature `float_layout`, default-on) — Buiy can express CSS `float: left/right` directly via Taffy; no Buiy-side float pass needed.
  - **`Direction::Ltr / Direction::Rtl`** — Buiy's writing-mode resolution borrows this for inline-axis flow. Vertical writing modes (`vertical-rl`, `vertical-lr`, `sideways-*`) still wait on upstream ([#752](https://github.com/DioxusLabs/taffy/issues/752)).
  See [layout-algorithms.md § 4](layout-algorithms.md), [layout-algorithms.md § 6](layout-algorithms.md).

- **`AvailableSpace::{Definite, MinContent, MaxContent}` as the size-resolution model.** Buiy's container queries reuse this enum for cq-unit resolution, and Buiy's intrinsic-sizing stubs (`Val::MinContent` / `MaxContent` / `FitContent`) translate to it. Validates: parameterizing layout entry points by available space rather than by definite-only dimensions. See [architecture.md § 5](architecture.md).

- **`unrounded_layout` + `final_layout` separation.** Taffy stores both per node since 0.7.1; rounded values are stable under animation, unrounded are needed for parent-position composition. Buiy reads `final_layout` exclusively today, but the unrounded path is available if Buiy ever needs sub-pixel composition for animation interpolation. See [architecture.md § 3](architecture.md).

## Avoid

| Pitfall | Source | Buiy mitigation |
|---|---|---|
| **Depending on `*-experimental-*` crate versions** (e.g. `=0.11.0-experimental-cache-fix.3`). These are Burns's scratch branches for cache-correctness work; Blitz pins them because cache correctness is load-bearing for it. Production embedders should not. | [governance.md § 6](governance.md), [open-problems.md](open-problems.md) | Pin Buiy's `Cargo.toml` to stable Taffy releases only (`taffy = "0.10"`). Treat any `-experimental-` version as "do not depend." Watch [#911](https://github.com/DioxusLabs/taffy/pull/911) for the productionized form, then bump. |
| **Assuming `Display::Inline`, `InlineBlock`, `InlineFlex`, `InlineGrid` exist.** They don't. The `Display` enum is `{Block, Flex, Grid, None}` only. | [api.md § 5](api.md), [open-problems.md § 8](open-problems.md) | Buiy carries the inline variants in its own `Display` enum and maps them to Taffy: `Inline` → block leaf with measure function, `InlineBlock` → `Block`, `InlineFlex` → `Flex`, `InlineGrid` → `Grid`. The "inline-ness" is paint-time / hit-test-time, not layout-time. |
| **Assuming `Position::Static`, `Position::Fixed`, or `Position::Sticky` work in Taffy.** Only `Relative` and `Absolute` exist. | [api.md § 5](api.md), [open-problems.md § 10](open-problems.md) | Buiy's `Position` enum carries all five; the bridge maps: `Static` → Taffy `Relative` with zero inset; `Fixed` → `Absolute` against the viewport root; `Sticky` → post-Taffy sub-pass 6a that reads scroll offset and overrides `ResolvedLayout.position`. |
| **Assuming `Overflow::Auto` works.** Taffy's `Overflow` is `{Visible, Clip, Hidden, Scroll}` — no `Auto`. | [api.md § 5](api.md) | Buiy carries `Overflow::y_auto()` etc. on its component; the bridge sets Taffy's `Scroll` and the post-Taffy write step renders a scrollbar only when `content_size > size`. The "scroll if needed" decision is Buiy's, not Taffy's. |
| **Counting on subgrid, masonry, anchor-positioning, container-queries from upstream Taffy.** All four are years-open in the issue tracker with no PRs. | [open-problems.md](open-problems.md), [critiques.md § 1](critiques.md) | Buiy implements **container queries** above Taffy (capped 2× re-layout per frame, Phase 5 landed) and **anchor positioning** as post-Taffy sub-pass 6d. **Subgrid** is a stub + `warn!` until upstream lands ([#468](https://github.com/DioxusLabs/taffy/issues/468) since 2023-04-24). **Masonry** is tier-E with no stub ([#910](https://github.com/DioxusLabs/taffy/issues/910)). Buiy does not commit to forking-Taffy-to-add-subgrid. |
| **Trusting Taffy's README on downstream users.** It claims Iced uses Taffy. Iced does not (no `taffy` in `iced/Cargo.toml`; Iced has its own per-widget `Widget::layout` protocol). | [ecosystem.md § 1](ecosystem.md), [integration.md § 4](integration.md) | When citing a downstream Taffy user (for buy-in arguments, comparisons, scale claims), verify via the actual project's `Cargo.toml`, not Taffy's marketing list. The actual major Dioxus-org consumer is **Blitz**, not Dioxus core or Iced. |
| **Assuming float / clear are unsupported.** True through 0.9.x; false at 0.10+. Float + Clear ship behind `float_layout` (sub-feature of `block_layout`, default-on) since 0.10.0 (2026-03-31). | [layout-algorithms.md § 4](layout-algorithms.md), [open-problems.md § 7](open-problems.md), [capabilities.md § 1](capabilities.md) | Buiy can use Taffy's float directly. Verify the inclusion against [Buiy foundation/visuals.md § 3.2](../../specs/2026-05-07-buiy-foundation/visuals.md#32-layout) before exposing; `shape-outside` remains tier-O (not modeled — Taffy floats are rectangular only). |
| **Bus-factor: single maintainer, no separate funding line for Taffy.** Nico Burns (independent, not employed by DioxusLabs) wrote and maintains the load-bearing work. DioxusLabs's VC funding (FutureWei + Khosla Series A) goes to Dioxus, not Taffy. No GitHub Sponsors integration on the repo. | [governance.md § 3 + § 7](governance.md), [critiques.md § 6](critiques.md) | Buiy can fork Taffy in a crisis — it's MIT-licensed and ~15k LoC. Document the fork-strategy in a Buiy spec's load-bearing-dep contingencies section; identify which subsystem (likely `buiy-layout`) would absorb the maintenance. Ramp cost is months; pre-stage by keeping `buiy-layout` tests against Taffy's exposed surface, not against Taffy internals. |
| **Cross-frame layout-invalidation churn.** Reconstructing the whole `TaffyTree` every frame defeats the cache. `tree.set_style` + `tree.set_children` auto-`mark_dirty`, so the cheap path is "stop calling them when nothing changed." | [integration.md § 6](integration.md), [architecture.md § 4](architecture.md) | Buiy uses Bevy's `Changed<Component>` on each of the ~15 decomposed layout components to gate the `SyncStyles` system. Only entities whose inputs changed re-emit a `taffy::Style`. The `LayoutTree` is a long-lived `NonSendResource`. |
| **Stale Taffy cache after measure-function context changes.** If the measure function depends on state outside Taffy (font sets, image decode results), Taffy can't know to invalidate. | [integration.md § 8](integration.md) | When cosmic-text shapes a font that wasn't available last frame, the text leaf must call `tree.mark_dirty(node_id)` for that entity. Encode this in `buiy-text-rendering-design`'s "font registration → mark layout dirty" contract. |
| **Tracking WPT conformance numerically.** Taffy doesn't publish a pass-rate. CHANGELOG carries per-test fix entries, not aggregates. | [ecosystem.md § 3](ecosystem.md), [critiques.md § 5](critiques.md) | Don't make Buiy claim "we pass X% of WPT." Describe Taffy's coverage as "WPT-derived" (1500+ generated + thousands imported from CSS WG / Chromium / Firefox / WebKit) without an aggregate number. Buiy's verification harness can import the same fixtures via the `scripts/import-yoga-tests` and `scripts/gentest` patterns. |
| **Holding Taffy's roadmap to its README "features in progress" list.** The README says "C bindings (WIP)" and "WebAssembly bindings (WIP)" — both point at draft issues that haven't moved in years. | [ecosystem.md § 4](ecosystem.md), [critiques.md § 4](critiques.md) | Treat Taffy's published roadmap as aspirational. Before depending on any "coming soon" feature, verify status via the actual issue ([#404](https://github.com/DioxusLabs/taffy/pull/404), [#345 roadmap](https://github.com/DioxusLabs/taffy/issues/345)) and the CHANGELOG, not the README prose. |
| **`Style.size = Dimension::Length(0.0)` instead of `Dimension::Auto`.** `Length(0.0)` collapses the node; `Auto` lets the algorithm pick. Bug source on every port. | [integration.md § 8](integration.md) | Buiy's `Val` enum defaults to `Auto` everywhere width/height-shaped, not `Px(0.0)`. The bridge must preserve this — converting `Val::Auto` to `Dimension::Length(0.0)` would silently collapse the node. |
| **`NodeId` is not `Entity`.** Taffy's `NodeId` is a `u64`-wrapping type; Bevy's `Entity` is something else. The embedder owns the map. `tree.remove` only frees one direction. | [integration.md § 8](integration.md), [api.md § 1](api.md) | Buiy's `LayoutTree` owns a `HashMap<Entity, TaffyNodeId>`. The `RemovedNodesGc` system (step 0 of the pipeline) calls `tree.remove(node_id)` and tolerates `Err(NotFound)` for parent-then-child despawn ordering. |
| **`Style` ergonomics: the `Length` / `LengthPercentage` / `LengthPercentageAuto` / `Dimension` split.** CSS-correct (different properties accept different value spaces) but a known ergonomics complaint — you can't have one "size" type that works everywhere. | [critiques.md § 3.1](critiques.md), [api.md § 4](api.md) | Buiy's `Val` enum unifies the author-facing space; the bridge translates per-field to the right Taffy type (`Val` → `Dimension` for `width`, `LengthPercentage` for `padding`, etc.). The complexity stays at the bridge; authors see one type. |
| **No CSS inheritance modeled.** Taffy doesn't have "the `direction` of my parent." If an embedder needs CSS-style inheritance, it walks its own tree first. | [critiques.md § 3.3](critiques.md) | Buiy resolves inheritance in private cache components (`WritingModeResolved`, `ContainingBlock`) before `SyncStyles`. Authors set on the parent; Buiy propagates to children; the bridge sees only fully-resolved values. |

## Borrow

Concrete primitives worth studying (and possibly direct adaptation into Buiy's own layers):

1. **`CompactLength` tagged-pointer optimization** for `Dimension` / `LengthPercentage` / `LengthPercentageAuto`. A pointer-sized union of `(Length | Percent | Auto | Fr | Calc(*const ()) | MinContent | MaxContent | FitContent)` — fits in a register, is `const`-constructible, and lets `calc()` carry an opaque pointer to an embedder-allocated AST. Buiy's `Val` enum currently uses a fat representation; if hot paths show value-type allocation cost, consider porting the tagged-pointer trick. The trade-off is that the value isn't a Rust enum anymore — match-on-Val becomes accessor-call-on-Val. See [critiques.md § 3.2](critiques.md).

2. **Const-construction discipline.** `Style::DEFAULT` + const helpers (`length`, `percent`, `auto`, `zero`, `fr`) → static styles cost nothing at runtime. Buiy's `Style` builder must preserve const-buildability so that authoring `const ROW: Style = Style { display: Display::Flex, ..Style::DEFAULT }` produces a const value. The same discipline applies to Buiy's decomposed components — `BoxModel`, `FlexParams`, etc. should be const-constructible from their inputs. See [api.md § 6](api.md).

3. **`MeasureFunc` for leaves.** Inline content (text, image, video) is opaque to Taffy; the embedder passes a closure with signature `FnMut(Size<Option<f32>>, Size<AvailableSpace>, NodeId, Option<&mut NodeContext>, &Style) -> Size<f32>`. The closure is what bridges cosmic-text shaping and image-asset sizing into layout. Buiy's text + image leaves register a `MeasureFunc` via `tree.new_leaf_with_context(...)`. See [api.md § 1](api.md), [integration.md § 6](integration.md).

4. **The `LayoutInput` / `LayoutOutput` round-trip protocol.** A clean stateless layout-call surface: input is `(known_dimensions, available_space, parent_size, axis, run_mode, sizing_mode, vertical_margins_are_collapsible)`; output is `(size, content_size, first_baselines, top_margin, bottom_margin)`. Stateless meaning: same inputs → same output (cache key). Buiy's container query re-layout pass benefits from the same shape — pure functions are cacheable. See [architecture.md § 4](architecture.md), [open-problems.md § 4](open-problems.md).

5. **Cache-tree separation in 0.7+.** `CacheTree` was split out of `LayoutPartialTree` so embedders can opt out of Taffy's caching or substitute their own. Decoupling the cache from the topology trait makes both independently swappable. Buiy currently relies on Taffy's per-node `Cache`; if Buiy ever wants a different cache strategy (e.g. a shared LRU across the tree), the trait split is the hook. See [architecture.md § 2](architecture.md).

6. **WPT-derived test corpus.** Taffy's `scripts/import-yoga-tests` + `scripts/gentest` pull fixtures from the W3C Web Platform Tests, Yoga's test suite, Chromium, Firefox, and WebKit. Buiy's verification harness should import the same fixtures — the tests don't care which engine runs them, so Buiy's bridge can be tested against the same conformance corpus. The corpus is the most valuable single artifact Taffy ships. See [ecosystem.md § 3](ecosystem.md).

7. **`Direction::Ltr` / `Direction::Rtl` per-container flag (0.10).** Inline-axis flow is a per-container property, not a global one. Buiy's writing-mode resolution borrows this — each container can independently switch LTR/RTL. Buiy extends with vertical-rl/lr/sideways modes, which Taffy doesn't yet ship ([#752](https://github.com/DioxusLabs/taffy/issues/752)). See [layout-algorithms.md § 6](layout-algorithms.md).

8. **CSS-spec-tracking treadmill discipline.** When Chromium changes layout behavior, Taffy ports the change (months later, but reliably). The CHANGELOG carries entries like `Fix resolving flexible lengths (WPT css/flexbox-multiline-min-max test)` and `CSS Grid aspect-ratio behaviour changed in Chrome 124`. Buiy should commit to the same discipline — when CSS WG ships a change or browsers fix an interop bug, Buiy's spec authors track the issue and port if relevant. The treadmill is a feature, not a bug, of being CSS-shaped. See [critiques.md § 7](critiques.md).

9. **`AvailableSpace` enum (`Definite(f32)` / `MinContent` / `MaxContent`).** The algorithmic input type for intrinsic sizing. Buiy's container queries reuse this enum for `cqw` / `cqh` / `cqi` / `cqb` unit resolution; Buiy's `Val::MinContent` / `MaxContent` / `FitContent` ultimately translate to `AvailableSpace` inputs (since they can't yet be `Dimension` values upstream — [#751](https://github.com/DioxusLabs/taffy/issues/751)). The enum is small, well-defined, and cacheable. See [architecture.md § 5](architecture.md).

10. **The umbrella-issue → discrete-fix-PR pattern.** Taffy's [#639](https://github.com/DioxusLabs/taffy/issues/639) was an umbrella "wire up WPT-derived tests" issue; the actual work landed as dozens of small fix PRs over multiple releases. Each fix is independently revertable, each test is independently verifiable. Buiy can adopt the same pattern for its own conformance work — one umbrella issue per CSS module, discrete PRs per spec deviation. See [ecosystem.md § 3](ecosystem.md).

11. **The umbrella roadmap-issue ([#345](https://github.com/DioxusLabs/taffy/issues/345)).** Taffy's public roadmap lives as a single GitHub issue, not as a `ROADMAP.md`. Long-term work is tracked there with links to per-feature issues. The pattern keeps the roadmap discoverable, comment-able, and naturally aging (closed issues drop off). Buiy can mirror — one `buiy-layout` umbrella issue linking to per-area children. See [governance.md § 5](governance.md).

12. **`detailed_layout_info` (post-layout computed-track introspection).** Feature-gated since 0.7.2; populates `DetailedGridInfo` after layout — computed track sizes, item rectangles, expanded auto-repeats. Bevy UI uses this for grid devtools. Buiy can expose the same surface via `ResolvedLayout`-shaped per-entity components for grid devtools and inspector widgets. See [layout-algorithms.md § 2](layout-algorithms.md).

## How to use this file

When designing a Buiy feature that touches layout, find the row in **Avoid** that names a Taffy pitfall close to your design and read the linked subsystem file for the full incident. Find the row in **Borrow** that names a Taffy primitive close to what you're designing and read the upstream Taffy source (or the cited file) for the shape, then adapt to Buiy's component model. **Promote any decision into a Buiy spec under `docs/specs/`** — this file is for capturing what we learn from Taffy, not for encoding Buiy's own decisions.
