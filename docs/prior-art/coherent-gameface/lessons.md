# Lessons for Buiy

This is the **consult-this-when-designing decision file**. The other files in this corpus are evidence; this file is the synthesis. Three sections — **Validates** (Buiy choices Coherent's experience confirms), **Avoid** (pitfalls to mitigate), **Borrow** (primitives worth studying).

## Top-level framing

Coherent Gameface is the **most ambitious "full HTML5 in a game engine" precedent**. Where NoesisGUI bets XAML and RmlUi bets a CSS subset, Coherent commits to **standards-compliant HTML5 + CSS3 + JavaScript** via an in-house engine (`Cohtml` + `Renoir`), shipping at AAA scale across Unity, Unreal, and custom engines. It validates the **web-platform-parity-ambition AT scale**, AND it validates the **cost** (proprietary, expensive, ~50–100 engineers, opaque pricing).

Buiy is the **open-source MIT/Apache analog targeting Bevy specifically**. The structural choice that lets Buiy reach the same ambition without Coherent's cost is **don't ship an HTML engine** — reuse Taffy + cosmic-text + AccessKit + wgpu, with BSN as the authoring layer instead of HTML.

The lessons read as: **what Coherent proves is shippable at AAA scale, what Coherent's proprietary cost reveals as expensive, and what concrete primitives Coherent designed well enough to study.**

## Validates

These Buiy design choices are confirmed by Coherent's market evidence:

- **Full HTML5/CSS3-flavored UI in a game engine is shippable at AAA scale.** Coherent ships in Borderlands 4, Marvel's Spider-Man 2, Civilization 7, Alan Wake 2, Minecraft, Sea of Thieves, World of Tanks, PUBG, and ~10 more named AAA titles. The thesis is not a green-field bet — it's a re-bet on a 14-year-proven pattern. Buiy's foundation [`README.md` § 1 goal 1 (web-platform parity)](../../specs/2026-05-07-buiy-foundation/README.md#buiys-goals-the-product) and [§ 1 goal 6 (game and app, both)](../../specs/2026-05-07-buiy-foundation/README.md#buiys-goals-the-product) are validated by Coherent's customer list.
- **Proprietary commercial UI middleware funds a custom HTML engine sustainably for 14 years.** Coherent has run continuously since 2012, through three substrate generations (Coherent UI WebKit → Hummingbird → Cohtml/Renoir). The market exists; the engineering can be done; the cost just shows up in license fees. **For Buiy this validates the substrate-reuse strategy** — the cost Coherent absorbs into pricing is the cost Buiy avoids by reusing Taffy + cosmic-text + AccessKit + wgpu rather than building an HTML engine. See [`distribution-and-governance.md`](distribution-and-governance.md).
- **In-process integration beats embedded-Chromium architecture for game UI.** Coherent's central technical argument — single-process, host-allocator-routed, host-thread-scheduled — is architecturally sound and shared across every successful game-UI middleware (Scaleform, NoesisGUI, RmlUi, Coherent). Buiy + Bevy ECS naturally operate this way (no out-of-process renderer, no IPC tax). Foundation [`architecture.md` § 2.3](../../specs/2026-05-07-buiy-foundation/architecture.md#23-what-buiy-owns) commits to a Bevy-render-graph-integrated pipeline, which is the same shape one level up the substrate stack. See [`hummingbird-vs-chromium.md`](hummingbird-vs-chromium.md).
- **CSS animations evaluated by the runtime (not via JS hot path) is the right pattern.** Coherent's docs explicitly recommend CSS3 animations over JS-driven animation, "evaluated in C++ for significantly faster performance." Buiy's animation sub-spec (foundation [`README.md` § 4 buiy-animation-design](../../specs/2026-05-07-buiy-foundation/README.md#4-sub-spec-roadmap)) commits to ECS-component-driven transitions + keyframes, evaluated in Rust on the `Update` schedule against `Time<Virtual>`. **Same shape, different substrate.**
- **Hot-reload of authoring assets without restart is foundation-tier.** Coherent ships live UI reload as a standard developer-productivity feature. Buiy commits to BSN hot-reload via Bevy's asset system (foundation [`README.md` § 5 component hot-reload open question](../../specs/2026-05-07-buiy-foundation/README.md#5-open-questions)). **Hot-reload is foundation-tier, not optional.**
- **A custom-render-pipeline GPU UI works at AAA console scale.** Renoir's command-stream rendering against DX12 / Vulkan / Metal / console-native APIs ships in PS5 / Xbox Series / Switch 2 titles. Buiy commits to a custom Bevy render-graph pipeline (foundation [`architecture.md` § 2.3](../../specs/2026-05-07-buiy-foundation/architecture.md#23-what-buiy-owns)); Coherent is the production-scale existence proof at the same shape one level up the abstraction stack.
- **Custom memory allocators + GPU memory tracking are AAA-table-stakes.** Renoir routes allocations through embedder-provided allocators and exposes `RenoirGPUMemoryInfo` for profiler attribution. Buiy should expose per-UI-subsystem GPU memory breakdown in the devtools sub-spec (foundation [`README.md` § 4 buiy-devtools-design](../../specs/2026-05-07-buiy-foundation/README.md#4-sub-spec-roadmap)).
- **Standards-compliant authoring beats invented-DSL authoring.** Coherent's HTML/CSS/JS pitch — "use the web platform you already know, with React / Preact / Tailwind / TypeScript / Webpack — is the strongest market differentiator. Buiy's BSN is **structurally analogous to UXML/HTML** (declarative, slot-shaped, reflection-driven asset). Foundation [`architecture.md` § 2.4](../../specs/2026-05-07-buiy-foundation/architecture.md#24-authoring-ecs-native-and-bsn-both-first-class). **Buiy authoring will feel familiar to web-platform authors; that's an explicit positioning bet.**
- **AAA studios pay for a complete UI library + engine integration even when engine-native UI exists.** Unity Studios with UGUI or UI Toolkit available, Unreal studios with Slate/UMG available — and still adopt Coherent for the comprehensive web-platform parity, better authoring tooling, and consultative support. Buiy's product surface — comprehensive widgets + a11y + theming + animations + dev tools — is what Bevy users will adopt over `bevy_ui` for the same reasons. **A comprehensive UI library is a viable product surface in the Bevy ecosystem.**
- **Authoring tool cross-platform-by-default beats Windows-only authoring chains.** Coherent's "use VSCode + Chrome + Webpack" works on Windows / macOS / Linux. By contrast, NoesisGUI requires Blend for Visual Studio (Windows-only). Buiy's text-based BSN works in any editor; the eventual visual inspector (devtools sub-spec) is also cross-platform. **Authoring is cross-platform by default.**

## Avoid

Pitfalls drawn from Coherent's posture, with Buiy's mitigation:

| Pitfall | Source | Buiy mitigation |
|---|---|---|
| **Proprietary HTML5-engine maintenance burden.** Cohtml must track Chromium's pace (container queries 2022–23, anchor positioning 2024, modern color 2023, view transitions 2024, scroll-driven animations 2024) indefinitely. ~50–100 engineers cannot outpace Chromium ~thousands. The gap is structurally permanent and grows. | [`critiques-and-open-problems.md`](critiques-and-open-problems.md) § 2; [`html5-coverage.md`](html5-coverage.md) "Modern CSS gap." | **Don't ship an HTML engine.** Reuse Taffy (layout, includes Grid + future container queries) + cosmic-text (text + BiDi + IME) + AccessKit (a11y) + wgpu (rendering). Maintenance bills stay on upstream communities. Foundation [`architecture.md` § 2.2](../../specs/2026-05-07-buiy-foundation/architecture.md#22-underlying-primitives-buiy-integrates-directly). |
| **Proprietary commercial licensing.** Coherent is closed-source, quote-based. Indies / mid-tier / open-source projects effectively excluded. Single-vendor risk for shipping AAA titles. | [`distribution-and-governance.md`](distribution-and-governance.md) "Pricing model"; [`critiques-and-open-problems.md`](critiques-and-open-problems.md) § 1. | **MIT-OR-Apache-2.0 dual permissive.** Source is the norm. crates.io distribution. No quote, no royalty. **Hard constraint, not negotiable.** |
| **In-process TTS as the a11y story (no OS-AT bridge).** Cohtml's `CohtmlARIA*` plugins call a JS SpeechAPI library — no UIA / AT-SPI / AXAPI tree publication. NVDA / VoiceOver / JAWS / TalkBack don't reach Cohtml UIs. User-preferred voice / verbosity / pronunciation don't apply. No braille. | [`critiques-and-open-problems.md`](critiques-and-open-problems.md) § 3; [`html5-coverage.md`](html5-coverage.md) "Cohtml-specific extensions." | **AccessKit-first** (foundation [`architecture.md` § 2.6](../../specs/2026-05-07-buiy-foundation/architecture.md#26-accessibility-accesskit-first)). OS-AT-bridged on Windows / macOS / Linux / Android / iOS. Decomposed `A11yRole` / `A11yLabel` / `A11yDescription` / `A11yStates` / `A11yRelations` components from day one. ACCNAME 1.2 name computation in `buiy_core`. **WCAG 2.2 AA floor.** This is Buiy's single biggest a11y differentiator vs Coherent. |
| **Custom JS-element for Grid replacing native CSS Grid.** `<gameface-grid>` is a Cohtml-specific element, not `display: grid`. Permanent ecosystem-divergence cost: no Stylelint, no MDN, no Chrome devtools grid inspector, JS overhead for layout. Same pitfall RmlUi commits with its `decorator:` syntax. | [`html5-coverage.md`](html5-coverage.md) "CSS Grid"; [`critiques-and-open-problems.md`](critiques-and-open-problems.md) § 6. | **Native CSS Grid semantics via Taffy.** Foundation [`architecture.md` § 2.2](../../specs/2026-05-07-buiy-foundation/architecture.md#22-underlying-primitives-buiy-integrates-directly). Already landed via plan `2026-05-09-buiy-layout-grid.md`. **No custom-element replacements for CSS-spec features.** |
| **Per-engine binding tax — 3 bindings (UE, Unity, custom C++) × ~quarterly engine cadences = ~8–10 engine-bump events per year.** Maintenance dominated by engine-tracking work, not core-framework work. | [`engine-integration.md`](engine-integration.md) "Comparison: per-engine binding overhead." | **Bevy-only** (foundation [`README.md` non-goals](../../specs/2026-05-07-buiy-foundation/README.md#non-goals)). 1 substrate × ~quarterly Bevy cadence = 4 events per year. Each Bevy minor is one migration, not three. ~3× cost reduction baked into the architectural decision. |
| **JavaScript engine licensing + dual-VM cost.** V8 + alternate-VM strategy for platforms where V8 cannot be redistributed. Cross-platform behavior subtleties; testing matrix doubles. | [`html5-coverage.md`](html5-coverage.md) "JavaScript"; [`hummingbird-vs-chromium.md`](hummingbird-vs-chromium.md) "JavaScript engine licensing." | **No JS runtime.** Logic in Rust ECS systems + observers + change detection. Foundation [`architecture.md` § 2.7](../../specs/2026-05-07-buiy-foundation/architecture.md#27-reactivity). Eliminates the entire JS-VM-licensing class of problems. |
| **"Develop in Chrome, ship in Cohtml" pitch has caveats.** All-elements-default-to-flex-column-order divergence, `calc()` not in `@keyframes`, mixed-unit `calc()` doesn't work, HTML subset (no `<iframe>`, no `<form>` URL submission, no `<input type="file">`), V8-vs-alternate-VM behavior splits. The pitch is directionally true but breaks at integration time. | [`critiques-and-open-problems.md`](critiques-and-open-problems.md) § 7. | **Buiy makes no "test in browser X, ship in Buiy" promise.** BSN is BSN; the test target is Buiy itself, the verification harness (foundation [`verification.md`](../../specs/2026-05-07-buiy-foundation/verification.md)) is the source of truth. Closer to how engine-native UI works; no false equivalence promised. |
| **Pricing opacity gates discoverability and onboarding.** Quote-based pricing means every prospective customer goes through sales. Indies / mid-tier / open-source projects de facto excluded. Long-tail discoverability is sacrificed for high-touch AAA sales. | [`distribution-and-governance.md`](distribution-and-governance.md) "Pricing model"; [`critiques-and-open-problems.md`](critiques-and-open-problems.md) § 4. | **crates.io + GitHub.** `cargo add buiy`. Zero friction. No sales motion. The discoverability + frictionless-adoption upside is what offsets lack of hand-holding. |
| **"Hellbender / Streamline Group acquisition ~2021"** pre-amble claim is **unverified** in this corpus. Most likely confusion with **Coherent, Inc.** (the laser/photonics company acquired by II-VI in 2022, renamed Coherent Corp — a different company entirely). | [`history.md`](history.md) "On the acquired-by-Hellbender claim"; [`distribution-and-governance.md`](distribution-and-governance.md) "Ownership." | When citing acquisition / corporate-event information in Buiy docs, always link to the primary source. Don't propagate unverified claims. |
| **No public CSS-spec absorption roadmap.** Coherent's public roadmap tracks per-version features but doesn't commit to "container queries by version X, anchor positioning by version Y." Studios shipping 3-year projects can't predict what'll be available in 2028. | [`critiques-and-open-problems.md`](critiques-and-open-problems.md) § 10. | Buiy's foundation [`visuals.md`](../../specs/2026-05-07-buiy-foundation/visuals.md) tier list **is** the public, auditable roadmap. Every web-platform feature is **F/C/E/O**-classified; the sub-spec roadmap in foundation [`README.md` § 4](../../specs/2026-05-07-buiy-foundation/README.md#4-sub-spec-roadmap) maps features to owning sub-specs. **Public roadmap is the foundation spec.** |

## Borrow

Concrete primitives worth studying and adapting from Coherent Gameface:

1. **HTML5 + CSS3 + JS as the UI authoring layer, structurally.** Coherent's biggest market pull is "use the web platform you already know." Buiy's BSN is intentionally shaped to feel familiar to that audience — declarative, slot-shaped, reflection-driven, hot-reloadable. **The structural pattern of "declarative tree, asset-loaded, hot-reloaded, reflection-resolved property values" is shared between HTML→Cohtml and BSN→Buiy.** See [`architecture.md`](architecture.md) § "Two-library substrate" and foundation [`architecture.md` § 2.4](../../specs/2026-05-07-buiy-foundation/architecture.md#24-authoring-ecs-native-and-bsn-both-first-class).

2. **The engine-binding pattern (engine-agnostic substrate + thin engine-specific bindings).** Coherent maintains 3 bindings (UE, Unity, custom C++) over the engine-agnostic Cohtml + Renoir substrate. Buiy explicitly skips this axis (Bevy-only), but the **conceptual split is right**: the substrate (Bevy ECS + Buiy components + Buiy render pipeline) is engine-agnostic-shaped within the Bevy ecosystem; userland code touches `buiy::*` types, not `bevy::ecs::*` types where possible. The lesson: **public Buiy API is uniformly engine-agnostic-shaped (no Bevy-specific types in user code outside plugin-installation), even though the runtime depends on Bevy internally.** Same lesson reaches Buiy from NoesisGUI's two-tier API split (see [`noesisgui/lessons.md`](../noesisgui/lessons.md) Borrow entry 1).

3. **The GPU command-stream rendering pattern with engine-owned command queue.** Renoir emits draw commands → host engine owns the GPU command queue → host engine decides when to submit, where to composite. Buiy uses Bevy's render graph at a finer granularity (render-pass nodes), which is the same shape one layer up. The **resource-barrier helpers Renoir exposes on DX12/Vulkan** are the right precedent for Buiy's render-pipeline sub-spec exposing barrier hooks to embedders who composite UI into custom render passes. See [`engine-integration.md`](engine-integration.md) § "Render hooks: Renoir as the integration seam."

4. **Custom memory allocator + GPU-memory tracking + per-subsystem attribution.** Coherent ships `RenoirGPUMemoryInfo` so profilers can attribute GPU memory to the UI subsystem. Buiy should expose a per-UI-subsystem GPU memory breakdown in the devtools sub-spec (foundation [`README.md` § 4 buiy-devtools-design](../../specs/2026-05-07-buiy-foundation/README.md#4-sub-spec-roadmap)). Bevy provides the substrate (`MemoryUsage`-style instrumentation); Buiy surfaces the UI-specific slice.

5. **"Subset of web platform optimized for game UI" as a feasibility study.** Coherent's empirically iterated subset (~14 years of customer feedback) tells us what AAA game UIs actually need: Flexbox (yes), Grid (need but the JS-element shape works for studios in practice), transforms (yes), filters/blend modes/masks (yes), animations (yes, prefer CSS), data binding (yes, declarative), gamepad input (yes, HTML5 API), TextToSpeech (in-process variant, marginal). Buiy's foundation [`visuals.md`](../../specs/2026-05-07-buiy-foundation/visuals.md) tier list intentionally **targets a strict superset** of Coherent's shipped surface, plus the deltas (native Grid, container queries, anchor positioning, modern color, OS-AT-bridged a11y). **Coherent's surface is the minimum-viable scope; Buiy's foundation tier list is the maximum-viable scope.**

6. **The split of "code-first developer product (Gameface)" and "artist-first product (Prysm, Adobe-Animate-driven)."** Coherent splits one runtime into two authoring-facing products to address different team roles (programmers vs animators). Buiy doesn't ship a separate artist tool, but the **BSN asset format must be visual-editor-friendly enough to support a future animator-driven authoring path** — that's the devtools sub-spec's responsibility. The lesson: **dual-authoring-paths over one runtime is feasible and AAA-supported.** Coherent Prysm is the Scaleform-succession case study. See [`architecture.md`](architecture.md) § "Two-product split."

7. **Templates + custom-element-style component decomposition.** Coherent ships `GameUIComponents` — a library of HTML Custom Elements (`<gameface-grid>`, `<gameface-virtual-list>`, `<gameface-dropdown>`, etc.) that wrap reusable behaviors as named, slot-shaped HTML elements. **The custom-element shape is the right precedent for Buiy's widget catalog primitives** — every Buiy widget is a small, named, slot-shaped, hot-reloadable BSN component. (Buiy diverges where CSS-spec features are involved — see Avoid row "Custom JS-element for Grid.")

8. **DevTools-style inspector + live-CSS-edit + layout overlay.** Coherent ships a Chrome-DevTools-equivalent inspector for Cohtml views. Studios use it daily. **Foundation-tier expectation** for any modern UI framework. Buiy's devtools sub-spec (foundation [`README.md` § 4](../../specs/2026-05-07-buiy-foundation/README.md#4-sub-spec-roadmap)) commits to inspector + layout overlay + AccessKit tree viewer + contrast linter + focus-order visualizer. Same shape.

9. **Console support discipline.** Coherent ships per-console SDK builds (Xbox One/Series, PS4/PS5, Switch / Switch 2). AAA studios buy specifically for the console-platform coverage. Same lesson NoesisGUI teaches (see [`noesisgui/lessons.md`](../noesisgui/lessons.md) Borrow entry 8). Buiy can't replicate exactly because open-source can't carry NDA'd console code, but **when Bevy gets first-class console support, Buiy should treat console support as foundation-tier, not a future tier-gated feature.**

10. **The "Scaleform-succession" market-positioning pattern.** Coherent deliberately positioned Gameface + Prysm to absorb the Scaleform customer base when Autodesk EOL'd Scaleform in 2017. The market moves; well-positioned alternatives capture displaced customers. **Buiy should monitor adjacent ecosystem displacements** — if a major Bevy-adjacent UI framework deprecates, Buiy is the natural successor for those users. See [`history.md`](history.md) "Comparison to peers" and foundation [`README.md` § 1 goal 6 (game and app, both)](../../specs/2026-05-07-buiy-foundation/README.md#buiys-goals-the-product).

## How to use this file

When designing a Buiy feature:

1. **Find the row in `Avoid`** that names a pitfall close to your design. Read the linked file for the source detail.
2. **Find the entry in `Borrow`** that names a primitive close to what you're designing. Read the linked file to understand the Coherent shape, then adapt for Buiy's ECS / open-source / Bevy-only / AccessKit-first architecture.
3. **Promote any decision into a Buiy spec** under `docs/specs/` — this file is for capturing what we learn from Coherent Gameface, not for encoding Buiy's own decisions.
