**Subject:** cosmic-text — Validates / Avoid / Borrow decision file for Buiy text work

This is the consult-this-when-designing-text file. Other files in the folder are evidence; this is synthesis. When designing any Buiy feature that touches text — `buiy-text-rendering-design`, `buiy-text-editing-design`, `buiy-asset-pipeline-design`, `buiy-i18n-design`, any widget with editable text — start here.

## Validates

These Buiy design choices are confirmed by cosmic-text's experience and architecture:

- **The cosmic-text choice itself.** A pure-Rust shape + layout + cursor + selection + glyph-cache stack composed from `harfrust` (HarfBuzz port) + `swash` (rasterization, color emoji) + `unicode-bidi` (UAX #9) + `skrifa` (font data) + `fontdb` (discovery) is the right architecture for Buiy. Each substrate crate has a single responsibility; the cosmic-text crate is the integration. See [`architecture.md`](architecture.md) and [`ecosystem.md`](ecosystem.md).
- **Producing rasterized glyph atlases, not vector path output.** cosmic-text emits `SwashImage` (CPU pixel buffers, alpha or RGBA); the embedder uploads to a GPU atlas and renders quads. This matches Buiy's render pipeline spec ([`architecture.md`](../../specs/2026-05-07-buiy-foundation/architecture.md#23-what-buiy-owns)), which commits to "cosmic-text → glyph atlas → render pass, owned end-to-end." Vector-path output (Parley + vello's path) is the alternative; Buiy bet on raster atlases.
- **BiDi via `unicode-bidi` + per-run shaping via `harfrust`.** Production-proven across COSMIC (~500-language UDHR fixture), Iced, and Bevy. UAX #9 segmentation is delegated to a single Servo-stewarded crate; cosmic-text adds no BiDi state machine of its own. See [`bidi.md`](bidi.md).
- **Color emoji via swash COLR/CPAL + sbix + CBDT/CBLC.** Covers Apple-style (sbix), Microsoft-style (COLRv0), and Google-style (CBDT/CBLC) emoji on the platforms that ship those formats. The gap is COLRv1 (Fedora 43+), which is upstream-blocked on swash. See [`critiques.md` § COLRv1](critiques.md).
- **Editor / Buffer split.** Since 2022-10-31 the `Editor` is a separate type wrapping `Buffer`. The Buffer holds text + attrs + layout; the Editor holds cursor + selection + in-progress Change. This clean separation lets Buiy compose them as it wishes — one Buffer per text node, optional Editor only on editable nodes. See [`editing.md`](editing.md).
- **System76 stewardship via COSMIC desktop dogfooding.** cosmic-text is not an experimental project — it ships in every COSMIC app daily. The bus-factor risk (single primary maintainer, single funding source) is real (see [`governance.md`](governance.md)) but the long-term-commitment signal is strong. Buiy depends on cosmic-text's continued existence; this dogfood pattern is the best non-foundation signal of that.
- **`FontSystem` singleton pattern.** Every production embedder ends up with one `FontSystem` per process (Iced, Bevy, COSMIC). Buiy keeps one per app, not per node. The non-`Sync` constraint means pin it to the UI thread or wrap in `Arc<Mutex<>>`. See [`integration.md`](integration.md).
- **The IME-is-an-embedder-concern boundary.** cosmic-text deliberately exposes editing primitives (`Action::Insert`, `Cursor`, `Change`) and leaves IME state to the embedder. This matches Buiy's design: winit gives Buiy `Ime::Preedit/Commit/Enabled/Disabled` events; Buiy translates to cosmic-text `Action::Insert` for committed text and maintains a parallel preedit span. See [`editing.md` § IME](editing.md#ime-composition-the-embedder-boundary) and Buiy's [text.md § IME composition](../../specs/2026-05-07-buiy-foundation/text.md).

## Borrow

Concrete primitives, types, and patterns from cosmic-text worth studying directly and possibly adapting into Buiy:

1. **The `Buffer` + `BufferLine` + `LayoutLine` + `LayoutGlyph` data model.** Clean separation of input text → line-segmented input → shaped layout → individual glyphs. Each layer caches lazily. Buiy adopts the same four-level model in `buiy-text-rendering-design`; the cached-shape-per-line pattern is exactly the rebuild granularity Buiy needs for low typing latency. See [`architecture.md` § Data model](architecture.md#data-model).
2. **`Attrs` + `AttrsList` for per-span styling.** Interval-map (`rangemap`) of byte-range → `Attrs { family, weight, style, stretch, color, font_features, letter_spacing, text_decoration, metadata }`. Buiy adopts a similar attrs-based span model for rich text rather than per-glyph styles. See [`architecture.md`](architecture.md), [`capabilities.md`](capabilities.md).
3. **`Wrap::None / Glyph / Word / WordOrGlyph` variant set.** Maps cleanly to Buiy's `white-space` and `overflow-wrap`: `None` ≈ `nowrap`, `Glyph` ≈ `word-break: break-all`, `Word` ≈ default, `WordOrGlyph` ≈ `overflow-wrap: anywhere`. Borrow the variant set. See [`capabilities.md` § Wrapping & breaking](capabilities.md#wrapping--breaking).
4. **`Align::Left / Right / Center / Justified / End` variant set.** Same shape as CSS `text-align: start | end | left | right | center | justify`. Buiy's text-align maps directly; `Justified` is inter-word only (no `text-justify` variant control). See [`capabilities.md`](capabilities.md).
5. **`Ellipsize::Start / Middle / End` (added in 0.18.0).** Direct support for `text-overflow: ellipsis` plus the less-common middle-truncation case. Borrow the variant set when wrapping `text-overflow` in Buiy's text component. See [`critiques.md` § text-overflow](critiques.md#text-overflow-ellipsis).
6. **The `Cursor { line, index, affinity }` model for BiDi-aware caret movement.** `affinity` (Before/After) disambiguates positions at level boundaries and soft-wrap boundaries. The `Motion` enum (`Left | Right | Up | Down | LeftWord | RightWord | ParagraphStart | ParagraphEnd | PageUp | PageDown | Vertical(i32) | GotoLine(usize) | SoftHome | SoftEnd | Home | End`) is visual-by-default and BiDi-correct without the embedder doing BiDi math. See [`editing.md` § Cursor movement](editing.md#cursor-movement-visual-vs-logical), [`bidi.md`](bidi.md).
7. **The `vi` feature pattern for opt-in editor extensions.** cosmic-text gates `modit` + `syntect` + `cosmic_undo_2` behind a Cargo feature so users who don't need vi-mode + syntax highlighting + undo don't pay the dep cost. Buiy can layer its own editor extensions (e.g. multi-cursor, find-replace UI) similarly behind features. See [`architecture.md` § Optional features](architecture.md#optional-features-cargotoml).
8. **`SwashCache` glyph caching strategy.** `HashMap<CacheKey, SwashImage>` where `CacheKey = (font_id, glyph_id, font_size_bits, x_bin, y_bin, font_weight, flags)` and `(x_bin, y_bin)` quantize subpixel positions to 4 bins per axis. Buiy's GPU atlas borrows this key model. The eviction story is left to the embedder — Buiy must add its own LRU since `SwashCache` is monotonically growing. See [`architecture.md` § Glyph cache and eviction](architecture.md#glyph-cache-and-eviction).
9. **The IME boundary contract.** winit `Ime::Preedit(text, cursor_range)` → Buiy parallel preedit span (rendered as decoration); winit `Ime::Commit(text)` → cosmic-text `Action::Insert(c)` for each char, grouped as single undo unit; winit `Ime::Enabled / Disabled` → Buiy IME-active flag. Clean state machine; no Buffer mutation during preedit. See [`integration.md` § IME boundary](integration.md#ime-boundary-in-detail), [`editing.md`](editing.md).
10. **The `Action` enum for editor commands.** A single verb set the embedder pushes into the editor: `Motion`, `Escape`, `Insert(char)`, `Enter`, `Backspace`, `Delete`, `Indent`, `Unindent`, `Click`, `DoubleClick`, `TripleClick`, `Drag`, `Scroll`. Buiy's text-edit command bus borrows the shape — input events translate to a single `Action`-like enum per keystroke / mouse event. See [`editing.md` § The Action enum](editing.md#the-action-enum).

## How to use this file

When designing a Buiy text feature: (1) Find the row in **Avoid** that names a pitfall close to your design, follow the linked file for the full evidence, and apply the mitigation; (2) find the row in **Borrow** that names a primitive close to what you're designing, read the cosmic-text source for shape, then adapt for Buiy's component model. Promote any decision into a spec under `docs/specs/` — this file is for capturing what we learn from cosmic-text, not for encoding Buiy's decisions.
