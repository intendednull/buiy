**Date:** 2026-06-25
**Status:** active
**Subject:** Web/WASM rendering path of the Bevy + wgpu + winit stack — the decision file (Validates / Avoid / Borrow)

This is the consumer-facing decision file for the folder: what the Bevy/wgpu/winit web path **confirms** about Buiy's wasm approach, the **traps** to design around, and the **patterns to copy**. Each bullet cross-links the evidence file that establishes it. It ties directly to `docs/reports/2026-06-25-wasm-browser-support-feasibility.md` — its two hard compile/limit fixes (**B1** arboard, **B2** 17-attribute band pipeline), the WebGL2 float-target item (**W1**), and the phased roadmap (P0 build-wiring → P1 backend → … → P4 fonts/CI).

## Validates

- **Buiy adds zero browser-bootstrap code, by design.** Buiy constructs no `Window`, sets no `WgpuSettings`/`Backends`, requests no adapter/device — Bevy owns every step. Buiy only ever *reads* `Res<RenderDevice>`, and reads it in `finish()` / prepare systems, exactly where Bevy guarantees the async-initialized device exists. No synchronous-adapter blocker is introduced. ([bevy-bootstrap](bevy-bootstrap.md) §4-§5.)
- **The renderer is WebGL2-downlevel-clean by construction.** No compute, no storage buffers, no MRT, no depth-stencil; format+sample-specialized pipelines; fragment-discard clipping. The storage/compute zeros in `downlevel_webgl2_defaults` simply do not bite a pipeline that uses none of them. ([wgpu-backends](wgpu-backends.md); feasibility §2.)
- **Single-thread is correct *and* free.** Buiy builds Bevy `default-features = false` with `multi_threaded` off; on wasm the `bevy_tasks` cfg-alias forces single-thread regardless. Buiy sidesteps the entire atomics + COOP/COEP + nightly + `build-std` rabbit hole, and a UI lib's latency-bound per-frame work gains nothing from parallelism Bevy doesn't even do on web. ([threading](threading.md).)
- **Text works on web with zero font-supply work for the MVP.** cosmic-text 0.19 + swash 0.2.9 + fontdb 0.23 are pure-Rust CPU shaping/rasterization, field-proven on wasm (glyphon, bevy_text). Buiy embeds its default font (`include_bytes!`), so Latin text renders with no fetch, no filesystem, no wiring. ([assets-and-fonts](assets-and-fonts.md).)
- **The a11y data/sink split is already web-ready.** Buiy's tree builder (`a11y/translate.rs`) is winit-free pure data; a future hidden-DOM/ARIA web sink consumes the same `build_tree_update` output the in-process driver already consumes. Only the sink is missing, not the tree. ([accessibility](accessibility.md).)
- **The closest shipping precedents target Buiy's exact envelope.** egui/eframe and Makepad — both custom GPU UI renderers, not games — ship to browsers on the WebGPU-first-with-WebGL2-fallback envelope Buiy plans. Vello (compute-only, WebGPU-only) is the counter-example Buiy's compute-free pipeline avoids. ([ecosystem](ecosystem.md).)

## Avoid

- **The WebGL2 16-vertex-attribute cap silently kills the band pipeline (B2).** `max_vertex_attributes = 16`; the border/outline `band.wgsl` declares 17 (`@location 0..=16`). Pipeline creation *fails* on any WebGL2 build, and the layout is a portability risk even on baseline-conformant WebGPU (spec baseline is also 16; desktop Dawn's ~30 only masks it). Packing the band to ≤16 attributes is a hard requirement for a WebGL2 build and spec-safety insurance for WebGPU. ([wgpu-backends](wgpu-backends.md).)
- **Do not assume one wasm binary covers both backends.** Bevy 0.19 resolves a single backend at compile time; bevy#13168 (single-binary runtime fallback) is open. Broad reach means **two artifacts + a JS feature-detect loader**, not a runtime switch — plan the build/CI/download path for two from the start. ([browser-support](browser-support.md), [open-problems](open-problems.md).)
- **Do not assume a11y or IME work on web.** AccessKit has no web adapter — a build pushes a correct `TreeUpdate` into a null adapter and reaches **zero** screen readers, silently. winit emits no `Ime::Preedit`/`Ime::Commit` on web (a canvas gets no `CompositionEvent`), so CJK/dead-key/accented input and the mobile soft-keyboard are dead until a hidden-input/`EditContext` shim is built *outside* winit. Any web milestone must disclose both gaps; they degrade safely (no crash) but block real usability. ([accessibility](accessibility.md), [winit-web](winit-web.md), [open-problems](open-problems.md).)
- **The sync `Clipboard` trait cannot wrap the async web clipboard, and `arboard` will not even compile (B1).** `arboard` is an ungated dep with no wasm backend = the one P0 compile blocker; gate it under `cfg(not(wasm32))` and default to `MemClipboard`. The web's only clipboard path is async, permission/gesture-gated `navigator.clipboard`, fundamentally incompatible with a synchronous `read()`/`write()` shape — a real bridge is later, separate work, not a trait the MVP can satisfy. ([winit-web](winit-web.md), [toolchain](toolchain.md).)
- **High-DPR startup can overflow `max_texture_dimension_2d` before anything renders.** A web surface is `logical_size × devicePixelRatio`; on DPR-3 phones / hi-dpi monitors that product (or a full-window compositor target derived from it) can exceed the adapter cap (commonly 4096 on WebGL2/downlevel and conservative mobile WebGPU), failing allocation *at launch*. Clamp offscreen/compositor target sizes to the live adapter limit and/or cap the effective scale factor. ([open-problems](open-problems.md), [winit-web](winit-web.md).)
- **Do not assume system fonts exist.** The browser exposes no font directory; `fontdb::load_system_fonts` is a no-op on wasm, and woff2 cannot be handed to the stack directly (fontdb decompresses no woff2 — non-goal). Non-Latin coverage is a font-*supply* task (embed or fetch the faces), not an engine task; the engine already handles the scripts. ([assets-and-fonts](assets-and-fonts.md).)
- **Two silent-correctness traps beyond B1/B2.** (W1) `Rgba16Float` effect-compositor targets need `EXT_color_buffer_float` on WebGL2 (core on WebGPU) or an `Rgba8Unorm` fallback — verify empirically. And sRGB/gamma on the negotiated web surface fails *silently* (wrong colors, no error) if the engine hands Buiy a non-encoding canvas view while Buiy pre-linearizes on the CPU expecting encode-on-write — check in-browser, fix with a final-pass encode if needed. ([wgpu-backends](wgpu-backends.md), [open-problems](open-problems.md).)
- **panic = abort means every web-reachable panic is fatal.** The headless gate never runs the render world, so render-extract panics (a historical Buiy footgun) only surface in-browser, where one panic kills the whole wasm instance. A wasm smoke-test lane (build + headless-browser load) belongs in CI before claiming web support. ([toolchain](toolchain.md).)

## Borrow

- **Bevy's `spawn_app` non-blocking runner.** On wasm, `event_loop.spawn_app(runner_state)` (winit `EventLoopExtWebSys`) returns control to the browser instead of `run_app`'s blocking loop. Buiy inherits this unchanged — the pattern to *not* fight: never block the browser main thread. ([bevy-bootstrap](bevy-bootstrap.md) §1, [winit-web](winit-web.md).)
- **The async-device `finish()` handoff.** Bevy detaches the adapter/device-init future onto the single browser executor and resolves it into `FutureRenderResources`, taken in `RenderPlugin::finish()`. Reading `RenderDevice` only in `finish()`/later systems makes a consumer correct on the async web path for free — the model Buiy already follows and should keep. ([bevy-bootstrap](bevy-bootstrap.md) §4.)
- **`WebAssetPlugin` (when Buiy ever fetches).** Bevy's HTTP asset source loads via `fetch` on wasm / `ureq` on native behind one `AssetReader` trait — but must be added *before* `AssetPlugin`, and folder-loading does not work on wasm. The pattern: embed the critical few, fetch the rest by explicit path. ([assets-and-fonts](assets-and-fonts.md).)
- **The `navigator.gpu` two-artifact feature-detect.** The standard Bevy-on-web reach pattern (and egui/eframe's posture): a tiny JS loader probes `navigator.gpu`, loads the WebGPU build when present, else the WebGL2 build. Copy it wholesale rather than waiting on bevy#13168. ([browser-support](browser-support.md), [ecosystem](ecosystem.md).)
- **Canvas-by-selector binding.** Bevy reads the `Window` component's `canvas: Option<String>` CSS selector and binds winit via `WindowAttributesExtWebSys::with_canvas`. Buiy's only web-bootstrap surface is configuration: set the selector, `fit_canvas_to_parent`, and `prevent_default_event_handling` (needed so wheel/touch don't scroll the page). ([bevy-bootstrap](bevy-bootstrap.md) §2, [winit-web](winit-web.md).)
- **egui's hidden-`<input>` IME shim.** The reference workaround for the winit web-IME gap (winit#4424) is an off-canvas hidden DOM input / `EditContext` that captures composition and forwards committed text — and it doubles as the mobile soft-keyboard trigger. Copy egui's approach; do not wait on an upstream winit fix for the web text-editing story. ([winit-web](winit-web.md), [open-problems](open-problems.md).)

## Roadmap tie-in

The feasibility report sequences these: **P0** = build-wiring (fix B1 arboard so `cargo build --target wasm32-unknown-unknown -p buiy` links; add `wasm32-unknown-unknown` to `deny.toml` targets); **P1** = WebGPU-first MVP (the band's 17 attrs survive on Chrome/Dawn, so the MVP needs no limit changes — but B2 (≤16 attrs) is advisable here too for cross-browser WebGPU reach, since baseline/mobile adapters may report the 16-attribute spec floor) → **then** the WebGL2 fallback build, where B2 becomes a *hard* requirement alongside W1 (`EXT_color_buffer_float` / `Rgba8Unorm`); later phases pick up sRGB/DPR verification, the IME/clipboard shims, the a11y DOM sink, and **P4** fonts/CI. Pin the wasm-bindgen CLI to the lock (0.2.125) in any wasm lane; do **not** add the getrandom `wasm_js` feature pre-emptively (it is absent from the production graph). See [toolchain](toolchain.md) and the report for the full sequence.
