**Date:** 2026-06-18
**Status:** active
**Subject:** bevy_ui — Validates / Avoid / Borrow decisions for the Buiy foundation

# Lessons for Buiy

This is the consult-this-when-designing decision file. The other files in this corpus are evidence; this file is the synthesis. Three sections — **Validates** (Buiy choices that bevy_ui's experience confirms), **Avoid** (pitfalls to mitigate), **Borrow** (primitives worth studying).

Before everything else: two findings reshape several existing Buiy assumptions.

## Top of file: two findings that reframe the Buiy foundation spec

### 1. BSN's baseline landed in 0.19. Buiy now pins the rc and authors real `bsn!`.

The BSN **baseline** merged via successor **PR #23413** (2026-03-27, milestoned Bevy 0.19, in the `bevy_scene` crate): the `bsn!` / `bsn_list!` macros + `Template` / `Scene` system. The original draft PR [#20158](https://github.com/bevyengine/bevy/pull/20158) never merged in its own form. Inline `bsn!` is the landed surface; the `.bsn` **asset-file loader** is still deferred upstream. As of 2026-06-18 Bevy 0.19 is rc-only (`0.19.0-rc.3`). See [`history.md`](history.md) § "BSN" and [`open-problems.md`](open-problems.md) § "BSN ergonomics maturity."

This updates the earlier "BSN has not landed; design *for* it" framing. Buiy has now taken a scoped **rc-pin policy exception** to reach `bsn!` authoring ([`2026-06-18-buiy-bsn-integration-design.md`](../../specs/2026-06-18-buiy-bsn-integration-design.md) §§ 1–2), so the foundation §2.4 BSN-authoring path moves from *by-construction readiness* to *actual authoring*. **The decomposition rule is unchanged and now pays off directly:** Buiy components are small, public-fielded, decomposed, reflection-registered — the tax paid in advance — so every author-facing component is `bsn!`-authorable today without retrofit (the common case satisfies BSN's `Clone + Default` template contract; issue #17644 remains the canonical demonstration of why megacomponents would have blocked this).

### 2. Post-0.19, bevy_ui and Buiy diverge on text shaper.

Bevy `main` (0.19-dev) migrated `bevy_text` from cosmic-text 0.16 to parley 0.9.0 + swash 0.2.6 (issue [#21765](https://github.com/bevyengine/bevy/issues/21765), opened 2025-11-06, labeled `Ready-For-Implementation` / `Blessed`). Buiy's foundation spec ([`architecture.md`](../../specs/2026-05-07-buiy-foundation/architecture.md) § 2.2) commits to cosmic-text directly.

This means: post-0.19, Buiy is **not on bevy_ui's text-rendering line**. cosmic-text shaping bugs, IME issues, BiDi caret behavior, atlas semantics — Buiy carries those independent of upstream Bevy. If cosmic-text upstream adoption thins because Bevy moved off it, Buiy still owns its commitment. The text pipeline is end-to-end Buiy's, and this is a load-bearing reason the parallel-stack decision pays for itself: text-shaper choice is not a Bevy-driven migration event for Buiy. See [`text-and-input.md`](text-and-input.md) § "Text rendering: a three-engine timeline."

## Validates

These Buiy design choices are confirmed by bevy_ui's experience:

- **Parallel-stack rationale (foundation README § 1.4).** bevy_ui's renderer gaps are real and structurally unresolved: non-rectangular clipping (issue [#9381](https://github.com/bevyengine/bevy/issues/9381), open since 2023-08), rounded-corner clipping bug (issue [#13093](https://github.com/bevyengine/bevy/issues/13093), open since 2024-04), transform-aware clipping (documented limitation), no `backdrop-filter` (no tracking issue), no `mix-blend-mode` / isolation (no tracking issue), no CSS top layer. Issue [#22345](https://github.com/bevyengine/bevy/issues/22345) (viridia, 2026-01-02) frames the fix as `"require substantial architectural redesign"` — the upstream-side timeline is years, not months. See [`architecture.md`](architecture.md) § "Renderer caps" and [`critiques.md`](critiques.md) § "The renderer feature gaps."
- **AccessKit-first (foundation architecture.md § 2.6).** Bevy has had AccessKit since 0.10 (March 2023) — three years of production integration. The integration is sound; the *component-model surface* over it (`bevy_a11y::AccessibilityNode`) was BSN-hostile and required PR #24308 (which added an `AccessibleLabel` sibling but did NOT break up the megacomponent). The pattern of "AccessKit is the right substrate, but the component surface above it must be decomposed" is exactly Buiy's choice — see [`text-and-input.md`](text-and-input.md), [`critiques.md`](critiques.md) § "The megacomponent problem."
- **BSN-friendly decomposed components (foundation goal 3).** Issue [#17644](https://github.com/bevyengine/bevy/issues/17644) is the canonical demonstration. viridia: `"Because of this, I can well imagine wanting to merge together multiple BSN templates, each of which has opinions about various accessibility attributes."` Megacomponents with private setters cannot be patched by layered BSN templates. Buiy's hard rule — small, public-fielded, observable, decomposed — is validated by this incident, and with BSN's baseline now landed in 0.19 (PR #23413) the rule pays off directly: every author-facing Buiy component is `bsn!`-authorable today (the `Clone + Default` template contract), no retrofit.
- **Taffy as the layout substrate (foundation architecture.md § 2.2).** bevy_ui has run on Taffy in production since 0.8 (July 2022, ~3.5 years). The Stretch → Taffy migration fixed an O(2^n) blowup bug. Taffy has shipped CSS Grid (0.3), block layout (0.4), float (0.10), named-line grid (0.9). Buiy integrates Taffy directly so it inherits all of this without going through bevy_ui — see [`layout.md`](layout.md).
- **cosmic-text choice through 0.18 (foundation architecture.md § 2.2).** Bevy shipped on cosmic-text from 0.15 (November 2024) through 0.18 (January 2026) — a year of production use. cosmic-text is also production in Iced, COSMIC Desktop, Zed, Lapce. Buiy commits to cosmic-text directly; even post-0.19 Bevy-side divergence, the upstream substrate has multiple consumers.
- **Decomposed visual components (foundation architecture.md § 2.3).** bevy_ui's own components have drifted *toward* decomposition over three releases: `BackgroundColor`, `BorderColor`, `Outline`, `BoxShadow`, `BackgroundGradient`, `BorderGradient` are all separate components on a node entity. See [`component-model.md`](component-model.md). The direction validates Buiy's commitment, even though bevy_ui's decomposition is non-monotonic (see the `BorderRadius` reversal in the Avoid section).
- **Render-graph integration via `UiMaterial` (foundation architecture.md § 2.3).** bevy_ui ships `UiMaterial` as the extension point for custom shader effects on UI nodes. Buiy's own render pipeline borrows this pattern. See [`architecture.md`](architecture.md) § "Render pipeline."
- **Per-window AccessKit adapter ownership (foundation architecture.md § 2.6).** Bevy's accessibility plugin is keyed to winit `WindowId`, not Bevy `Entity`. Buiy follows the same key. See [`distribution.md`](distribution.md) § "Coexistence with other Bevy crates."

## Avoid

Pitfalls drawn from bevy_ui's experience, with Buiy's mitigation.

| Pitfall | Source | Buiy mitigation |
|---|---|---|
| **Megacomponents that are BSN-hostile** — `bevy_a11y::AccessibilityNode` bundled all a11y properties as private fields behind inconsistent method-style setters. BSN couldn't patch them. PR #24308 added a partial sibling-component mitigation after the fact; the megacomponent is unchanged. | Issue [#17644](https://github.com/bevyengine/bevy/issues/17644); [`component-model.md`](component-model.md) § "Issue #17644"; [`critiques.md`](critiques.md) § "The megacomponent problem." | Decomposed `A11yRole` / `A11yLabel` / `A11yDescription` / `A11yStates` / `A11yRelations` from day one. No private-setter components. Every Buiy component is small, public-fielded, observable, decomposed. Foundation architecture.md § 2.4, 2.6. |
| **Renderer that caps web-parity features** — non-rectangular clipping, `backdrop-filter`, `mix-blend-mode`, isolation, true top layer are absent or buggy. Fixing them requires `"substantial architectural redesign"` (viridia, issue #22345). | [`architecture.md`](architecture.md) § "Renderer caps"; [`critiques.md`](critiques.md) § "The renderer feature gaps." | Own the render pipeline. Buiy implements rounded clipping, `clip-path` shapes, `backdrop-filter`, `mix-blend-mode`, true top-layer compositing, gradients in any color space, border-image, drop-shadow as first-class Bevy render-graph passes. Foundation architecture.md § 2.3. |
| **Mis-tracking which BSN PR/version landed** — the original draft PR #20158 never merged in its own form; the BSN baseline landed via successor **PR #23413** (2026-03-27, **0.19**, `bevy_scene` crate), and only inline `bsn!` (the `.bsn` asset loader is still deferred). An earlier pre-amble's "BSN landed in 0.18" claim was wrong on both PR and version. | [`history.md`](history.md) § "BSN"; [`open-problems.md`](open-problems.md) § "BSN ergonomics maturity." | Track the #20158-draft → #23413-merged lineage and the rc-only status. Buiy pins `0.19.0-rc.3` to author real `bsn!` (scoped policy exception, `2026-06-18-buiy-bsn-integration-design.md` §§ 1–2) and still targets inline `bsn!` only, deferring the `.bsn` loader with upstream. See top of this file. |
| **Coupling text rendering to a single shaper** — Bevy switched from ab_glyph (≤0.14) → cosmic-text (0.15–0.18) → parley + swash (0.19-dev) in three releases. Each migration is breaking and large. | [`text-and-input.md`](text-and-input.md) § "Text rendering: a three-engine timeline"; issue [#21765](https://github.com/bevyengine/bevy/issues/21765). | Own the text pipeline end-to-end. Buiy commits to cosmic-text and integrates directly; if upstream Bevy migrates away, Buiy still owns its commitment. Text-shaper choice is decoupled from Bevy minor releases. Foundation architecture.md § 2.3. |
| **Per-frame full layout rebuild** — bevy_ui's old performance issues (#677, #276, #2451) trace to insufficient layout caching. The situation has improved with Taffy 0.6+ but there is **no published bench at 1000+ nodes** and the cheat-book documents "a few hundred microseconds" per frame at moderate counts. | [`critiques.md`](critiques.md) § "Performance critiques"; [`open-problems.md`](open-problems.md) § "Verifiable behavior." | Change-detection + dirty-propagation through the layout pipeline; Taffy's own cache is the lower bound. The Buiy verification harness (foundation README § 1.7) explicitly enumerates productivity-app fixtures at 1000+ nodes. |
| **Treating `bevy_a11y` as a coexistence partner** — even with PR #24308's partial `AccessibleLabel` sibling, bevy_a11y still ships the megacomponent; the partial decomposition serves bevy_ui's needs, not Buiy's. Layering over it would mean reflecting Buiy's a11y state through bevy_a11y's components. | [`critiques.md`](critiques.md) § "The megacomponent problem"; [`open-problems.md`](open-problems.md) § "Accessibility tree completeness." | Replace bevy_a11y for any window where Buiy is present. Buiy owns the AccessKit adapter directly; `ActionRequest` events route to Buiy entities via Buiy's own plumbing, not bevy_a11y's. Foundation architecture.md § 2.6. |
| **Non-monotonic decomposition** — `BorderRadius` was a separate component in 0.17, then demoted back to a field on `Node` in 0.18 because "the field was small enough that keeping it as a separate component cost more than it bought." Reversing decomposition is breaking and forces consumer churn. | [`architecture.md`](architecture.md) § "Node / Style / ComputedNode decomposition"; [`component-model.md`](component-model.md) § "The decomposition migration." | Commit to a target decomposition in [`/home/user/buiy/docs/specs/2026-05-07-buiy-foundation/architecture.md`](../../specs/2026-05-07-buiy-foundation/architecture.md) and don't reverse it without a spec update. "If a property might end up shared across many nodes or hot-reloaded independently, it gets its own component" is the heuristic. |
| **No flagship game = no UX battle-testing** — bevy_ui has not yet been used at scale in a flagship commercial title. Tiny Glade (the most-cited Bevy commercial release) wrote its own UI renderer. Foresight Spar / Roboquest / other large titles do not verify as bevy_ui consumers. | [`ecosystem.md`](ecosystem.md) § "Game studios using bevy_ui"; [`critiques.md`](critiques.md) § "Performance critiques." | The Buiy verification harness (foundation verification.md) explicitly enumerates productivity-app fixtures *and* game scenarios, with named CI gates + manual release gates. Buiy commits to "Game and app, both" (foundation README goal 6) and doesn't outsource the proof to deployment. |
| **"Comprehensive" rhetoric in lieu of feature claims** — bevy_ui marketing uses words like "comprehensive" without naming features. The 10 Challenges (TimJentzsch, [#11100](https://github.com/bevyengine/bevy/issues/11100), open since 2023-12) is the closest the Bevy community has to a UI capability benchmark, and as of late 2023 no Bevy UI framework had cleanly demonstrated all 10. | [`critiques.md`](critiques.md) § "The 10 Challenges." | The Buiy spec separates **F** (foundation) / **C** (core) / **E** (extended) / **O** (out, explicitly excluded) tiers per feature, verifiable per tier (foundation README § "Tier legend"). |
| **AccessKit version pin drift** — `bevy_feathers` HEAD depends on accesskit 0.24; v0.17.3 stable depended on accesskit 0.21. Mid-release AccessKit majors break ABI for downstream consumers. | [`component-model.md`](component-model.md); [`ecosystem.md`](ecosystem.md). | Pin AccessKit explicitly per Buiy release. Foundation README § 5 lists "AccessKit cadence policy decoupled from Bevy" as an open question; treat it as live, not a footnote. Document the AccessKit version each Buiy release pins to in the release notes. |
| **Per-app reinvention of a focus model** — bevy_ui splits focus across `bevy_ui::focus` (mouse), `bevy_input_focus` (keyboard, Bevy 0.16+), `bevy_ui::auto_directional_navigation` (spatial, Bevy 0.18+), and widget-local APG contracts. No single coherent focus tree with `:focus-visible` semantics, traps, restoration, `inert`. | [`text-and-input.md`](text-and-input.md) § "Focus model." | Buiy owns a single focus tree with `:focus-visible`, traps, restoration, inert subtrees, roving tabindex, `aria-activedescendant`, sequential-focus-navigation-starting-point, spatial gamepad nav. Foundation architecture.md § 2.3. |
| **Lightweight RFC process** — Bevy's design state lives across GitHub Discussions, draft PRs, HackMD docs, Discord channels. The 22-month BSN saga (discussion #14437 → PR #20158 still draft) is the cost. | [`governance.md`](governance.md) § "RFC process." | Buiy keeps a canonical doc log in `docs/specs/` + `docs/plans/` + `docs/reports/` + `docs/prior-art/`. No design state in Discord. The `docs/README.md` master index is the only entry point. |

## Borrow

Concrete primitives worth studying and adapting:

1. **`RequiredComponents` mechanism (Bevy 0.15+, PR #14791).** `#[require(...)]` on a `Component` derive auto-inserts default-constructed companion components when the marked component is inserted. `Node` is the canonical heavy user — spawning `Node` pulls in `ComputedNode`, `UiTransform`, `UiGlobalTransform`, `Visibility`. Buiy components use this for the BSN-friendly idiom (every Buiy widget component requires its visual + a11y + layout companions). See [`component-model.md`](component-model.md) § "RequiredComponents: the mechanism." Caveat: issue [#18779](https://github.com/bevyengine/bevy/issues/18779) ("Required components behave unexpectedly for UI") is still open; corner cases exist.

2. **`Node` / `ComputedNode` input-vs-output split.** `Node` holds authoring input (layout fields, decoration). `ComputedNode` holds laid-out output (resolved size, position, scroll position). Read-only-for-users / written-by-pipeline. Clean separation that makes layout idempotent and observable. Buiy's `BuiySet::Layout` → `BuiySet::Style` ordering relies on the same split. See [`architecture.md`](architecture.md) § "Node / Style / ComputedNode decomposition."

3. **`ZIndex` + `GlobalZIndex` two-stage stacking.** bevy_ui supports both a local `ZIndex` (within the same stacking context) and `GlobalZIndex` (escape the local context). Buiy's stacking-and-top-layer spec (in `docs/specs/2026-05-08-buiy-layout-design/`) should study this two-stage pattern before designing its own top-layer-vs-z-index resolution. See [`layout.md`](layout.md).

4. **`Outline` as a separate component.** `Outline` is decomposed from `Node` (drawn outside the border edge, does not affect layout). Buiy follows the decomposition principle for `Outline`, `BackgroundColor`, `BorderColor`, gradients, shadows. See [`styling.md`](styling.md) § "Core styling primitives."

5. **`bevy_picking` backend registration pattern.** bevy_ui registers a picking backend (when its `bevy_picking` feature is on) rather than implementing hit-testing only internally. Each rendering crate (sprites, mesh, UI) registers its own backend; backend priority is configurable per pointer. Buiy registers its own `bevy_picking` backend in parallel to bevy_ui's. See [`text-and-input.md`](text-and-input.md) § "Input: bevy_picking integration", [`distribution.md`](distribution.md) § "Coexistence."

6. **Taffy bridging via `MeasureFunc` for leaf widgets.** Text and images measure their intrinsic content size by registering a measure callback with Taffy; Taffy calls back into Bevy during layout to learn the leaf's required size. Cleanly separates content-measurement (bevy_ui's responsibility) from layout-solving (Taffy's). Buiy uses the same pattern — `buiy_text` registers a measure for text nodes, `buiy_core` for image nodes. See [`architecture.md`](architecture.md) § "Taffy integration", [`layout.md`](layout.md).

7. **AccessKit integration plugin (`bevy_a11y`, despite its flaws).** The *mechanics* of the integration are sound: `AccessibilityRequested` resource gates whether the AccessKit tree is built (lazy), winit `WindowId` keys the adapter, `ActionRequest` events from the adapter route back into Bevy's input system. Only the *component surface* (`AccessibilityNode` megacomponent) was wrong. Buiy borrows the mechanics, replaces the surface. See [`critiques.md`](critiques.md) § "The megacomponent problem", [`open-problems.md`](open-problems.md) § "Accessibility tree completeness."

8. **`ViewVisibility` propagation for hide/show subtrees.** Bevy's visibility system propagates `Visibility::{Visible, Hidden, Inherited}` through hierarchies and exposes `ViewVisibility` as the resolved-per-camera output. Buiy uses this directly — `Display::None` short-circuits layout, `Visibility::Hidden` short-circuits rendering only, `inert`-style subtrees short-circuit focus / picking / a11y. See [`text-and-input.md`](text-and-input.md) § "Focus model."

9. **`UiMaterial` for custom shader effects on UI nodes.** The documented extension point for visual effects bevy_ui doesn't ship natively. Buiy's render pipeline ships its own analog — `BuiyMaterial` — for custom shaders on a Buiy node, with built-in materials for solid fill, gradients, image, masked image, and material slots for app-side custom shaders. See [`architecture.md`](architecture.md) § "Render pipeline" (#6).

10. **The `Display::None` short-circuit in layout.** When a `Node` has `display: Display::None`, Taffy skips the subtree entirely — no layout work, no extracted render data, descendants don't lay out. This is the load-bearing primitive for hide-without-paying-for-it. Buiy carries this contract verbatim. See [`layout.md`](layout.md).

11. **`AutoDirectionalNavigation` algorithm (Bevy 0.18+).** Spatial gamepad / arrow-key navigation: manual edges in `DirectionalNavigationMap` take priority; fallback computes best candidate by `CompassOctant` direction filtered by visibility + screen-bounds + target-camera. The algorithm is comparable to `iyes_ui_navigation` but ships with the engine. Buiy's focus model unifies this with sequential nav (Tab); the spatial-search algorithm itself is directly borrowable. See [`text-and-input.md`](text-and-input.md) § "Gamepad / spatial navigation."

12. **`OverrideClip` for popovers escaping scroll ancestors.** When a popover lives inside a scrolling container but needs to render outside its parent's clip rect, `OverrideClip` opts the descendant out of inherited clipping. Narrower than CSS `position: fixed` / true top layer but covers the common popover case. Buiy's popover / tooltip / menu spec should study this pattern before designing its own. See [`layout.md`](layout.md) § "Scroll containers / overflow."

## How to use this file

When designing a Buiy feature:

1. **Find the row in `Avoid`** that names a pitfall close to your design. Read the linked file for the original incident.
2. **Find the entry in `Borrow`** that names a primitive close to what you're designing. Read the linked file to understand the bevy_ui shape, then adapt for Buiy's component model (decomposed, public-fielded, observable, reflection-registered).
3. **Promote any decision into a Buiy spec** under `docs/specs/` — this file is for capturing what we learn from bevy_ui, not for encoding Buiy's own decisions.
