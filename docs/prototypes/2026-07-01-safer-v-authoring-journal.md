  - `cargo run -p safer_v_proto --bin capture_counter` → 2 GPU PNGs, **viewed**: frame 0 = "Count: 0", `−`/`+` bright, **Reset dimmed** (disabled at 0); frame 3 = "Count: 3", **Reset bright** (re-enabled). The `on_press_maybe(None)` handler detach + dim, and its re-attach + un-dim, are visible in the pixels.
  - **DX-3 PROVEN:** `counter.rs` has **zero** routing systems and **zero** bind systems. A synthesized `OnPress` on `+` flows `route_presses<M>` → real `enqueue` → MVU drain → model=3. The press payload is a typed `PressAction<M>(Msg)` **component (no stored closure)**, so record/replay survive — the MVU point holds.
  - **DX-2 + patch-in-place PROVEN:** the test pins the label id + all button ids, drives 0→3 then Reset→0, and asserts **every entity id is unchanged** across folds and across the Reset handler attach/detach. The reconciler patches `Text.0`/`A11yLabel`/`Opacity`/`PressAction` in place — it never rebuilds the subtree on a value change.
- **Surprised by / friction (journal → seeds the final's re-decisions):**
  1. **`Style` is a `Bundle`, not a Component** (the known F4 gotcha) → `.gap`/`.padding` decompose into several components at spawn, so the reconciler only applies **container style at spawn, never patches it**. Fine for static containers (Counter); a production reconciler needs a **decomposed-style patch path** (`FlexGap`/`BoxModel`/`FlexParams`). **Biggest structural limitation of W1** — this is F4 biting the reconciler, and confirms the final must make styling patchable (component-shaped), not Bundle-shaped.
  2. **Widget internal structure leaks into the reconciler:** a `Button`'s label is a *child* `Text` + a root `A11yLabel`, so patching a label means walking to the child. Reused the `Button::new` **Bundle** ctor (smooth under `world.spawn`) over the `button()` **Scene**-fn (would need `spawn_scene`+`ScenePlugin`). The final needs a clean "what is this widget's label slot" contract so the reconciler isn't coupled to each widget's child layout.
  3. **`ui()` is genuinely ONE call** — but had to spell `register_type + add_model + add_reducer` rather than `mvu_model()`, because `mvu_model` infers `M` from the reducer only, leaving `view`/`init` unconstrained. (A `ui()` that pins `M` from all three is the right shape.)
  4. **Frame timing:** the reconciler runs in `MvuSet::Bind` (after `BuiySet::Layout`), so structurally-new nodes lay out one frame late (fine under settling); value patches re-layout next frame. **A production reconciler wants to run before layout.**
  5. `.align_center()` doesn't visibly center a content-sized root (nothing to center against) — cosmetic, same as the hand-bind demos.
  6. `Children` iteration: the `composites.rs` `flat_map(|c| c.iter().copied())` idiom didn't type-check here (`Copied<Copied<…>>`); `.map(|c| c.to_vec())` via `Children: Deref<[Entity]>` was the clean fix.
- **Verdict (W1):** the reconciler+router thesis **holds on the Counter** — it deletes the demos' `route_counter_press` (DX-3) and `bind_counter_label` (DX-2), routes through the real MVU funnel (replay-safe), and patches in place. No blockers. Two things W2/W4 must attack surfaced here: **position-only child diffing** (a front-insert would churn everything → needs keyed reconcile, W2) and **container-style patching** (needs decomposed-style, W4/final).

### 2026-07-01 — Wave 2: `keyed_column` + editor bridge + TodoMVC (+ the replay wall)

- **Built (extends `lib.rs`, does not rewrite):** `keyed_column(iter, key_fn, view_fn)` (required-key list) + a **keyed child reconcile** (match rows by `RowKey`, spawn-new / despawn-gone / **reorder-in-place** without rebuild); `checkbox(checked).on_toggle(f)` onto the real `buiy_widgets::Checkbox`; `text_input(value).on_input(f).on_submit(msg).placeholder(s)` onto the real command-sourced `TextInput`; two new library-generic routers (`route_text_input` reads `TextChanged`, `route_text_submit` reads `EditSubmitted`); the model now spawns with a stable `LogicalId(MODEL_LID)` (replay identity). New app: `src/todomvc.rs` (**Model+Msg+update+view+seed+install ONLY** — zero route/bind systems) + `bin/{todomvc,capture_todomvc}`; `tests/todomvc.rs` (keyed / editor / replay).
- **Ran + VERIFIED MYSELF (not trusting green):**
  - `cargo test -p safer_v_proto` → **6/6** (3 W1 reconcile + 3 W2). `cargo run -p safer_v_proto --bin capture_todomvc` → **2 GPU PNGs, VIEWED**: seed = card + draft input(+Add) + 3 keyed rows `[checkbox|title|X]` (Walk-the-dog checked) + "**2 items left**" + Clear-completed; after a REAL `OnPress` on Buy-milk's checkbox → Buy-milk checked + "**1 items left**". The whole loop (pick→route→drain→reconcile→visual+derived-count) is in the pixels.
- **Keyed reconcile — HOLDS.** Test seeds ids{0,1,2}, snapshots each row's entity id, then toggles the middle, adds a row (id 3), removes the first. Assertion passes: **surviving rows kept their EXACT entity ids** (`row[1]`,`row[2]` unchanged across toggle+add+remove), only id0's row despawned + id3's spawned fresh, and the surviving checkbox's real `A11yToggled` reflects the toggle. Position-only churn (the W1 limitation) is gone.
- **Editor bridge — clean for the draft, with a sharp asymmetry.** `text_input(draft).on_input(TodoMsg::SetDraft).on_submit(TodoMsg::Add)` reads beautifully **because `TodoMsg::SetDraft` IS a `fn(String)->Msg`** (an enum tuple-variant ctor) — so `on_input` takes a **bare fn pointer**, stored on the entity, determinism-safe by type, no boxed closure. `on_submit` is a plain value. The command-sourced editor forced: (1) **controlled sync uses the low-level `apply(SelectAll,Insert/Delete)` seam, NOT the recorded keyboard system** — so the reconciler's value-set emits no `TextChanged` and writes no `EditLog` entry (no feedback loop, no log pollution); (2) **clear ≠ `Insert("")`** — `Insert("")` has no chars so it never deletes the selection; the reconciler must `SelectAll`+`Delete` to clear (the DX-6 "clearing rides a different channel" friction, now inside the surface). The draft lives in the model (`SetDraft` per keystroke; `Add` reads+clears), so the todo list is a **pure function of the message log**.
- **THE REPLAY WALL (§7.4) — the headline finding: the "one model + derived view" shape SIDESTEPS the wall.** Recorded an add("Task A")+toggle(0)+remove(2) session, replayed the unified log into a fresh same-seed app. **The whole `TodoApp` model (items + done flags + draft + next_id) replays STATE-IDENTICALLY** (`assert_eq!(replayed, recorded)` passes), and the reconciled keyed tree + the checkbox visuals re-derive to match. Measured: **10 widget folds + 6 editor commands; 7 entries dead-letter on replay** — the 6 editor `Insert`s (field LID unresolved) + the 1 checkbox-leaf `ToggleMsg` (checkbox LID unresolved). **Every one of those 7 dead-letters is HARMLESS**, and **zero model-targeted folds dead-letter**. *Why it holds where the gallery's `mvu_whole_ui_replay` gap test breaks:* the gallery makes each checkbox its OWN truth (a fixed leaf model with a stable LID) and a raw spawn is off-log → unrecreatable. Safer-V puts ALL structural truth in the ONE `TodoApp` model (on-log, stable LID) and routes toggles/edits to it as funneled `Msg`s; the rows/checkboxes/field are **pure derived view** re-spawned by the reconciler from the replayed model. So the §7.4 "structural ops are off-log" gap costs nothing: the off-log children's own log entries dead-letter, but the reconciler rebuilds them (with correct state) from the model that DID replay. **This is a real architectural result for the FINAL: an Elm/Iced-shaped `view(model)` surface makes whole-UI replay a property of the model alone.** (Caveat: byte-identical *editor internals* — caret/selection of a mid-edit field — still need stable field LIDs; only the *value* is model-reconstructed. Not relevant to TodoMVC.)
- **Borrow/closure ceremony — mild, and the surface dissolves the worst case.** The per-row `on_toggle(move |_| TodoMsg::Toggle(id))` DOES capture `id` — but `on_toggle` **eagerly evaluates `f(!checked)` at build time** into a concrete `PressAction` value, so the capture never outlives the `view` call and nothing is stored. No `Rc`/lifetime fight, no boxing. The asymmetry to report: **toggle can resolve its closure eagerly (target is deterministic given `checked`); `on_input` cannot (value is only known at keystroke time)** → `on_input` is constrained to a bare `fn` (fine for `Msg::SetDraft`; a *capturing* per-row `on_input`, e.g. inline title edit `move |s| Edit(id,s)`, would need a boxed `Fn` on a component — the residual V-cost the FINAL must weigh).
- **Checkbox friction (the real widget fought back a little).** The core's `advance_toggle_on_press` leaf ALWAYS fires on a checkbox press (can't be suppressed per-widget), so a click double-folds: the leaf flips `A11yToggled` (immediate visual) AND my router enqueues `Toggle(id)` (the model). They **converge** (reconciler re-asserts `A11yToggled` from `done` via a single-writer `ToggleMsg::Set`-on-drift, so no flicker) — but it means the surface can't cleanly *own* the checkbox; it shares it with the widget's built-in opinion. Works, but the FINAL should decide whether a "controlled leaf" mode (suppress the built-in toggle) is worth it.
- **Surprises:** (1) the drain **records every folded msg, even idempotent `set_if_neq`-noop ones** (`messages_recorded` bumps *before* the change test) — so a reconciler that enqueues a controlled `Set` every frame would flood the log; the fix (enqueue only on real drift) is load-bearing. (2) The model MUST carry a `LogicalId` or replay dead-letters ALL its folds (frame-1 lesson — the `ui()` model spawn now stamps one). (3) `TextEditState::apply` (low-level) vs `apply_keyboard_edits` (system) is exactly the record/no-record seam — the controlled path lives on the quiet side by design.
- **Verdict (W2):** keyed reconcile + the editor bridge **hold**, and the replay wall is **not a wall for this architecture** — the single most important finding. No W3 blocker. Open for W3/FINAL: container-style patching (still spawn-only, F4), the checkbox "controlled leaf" question, a boxed-`Fn` path for capturing `on_input`, and byte-identical editor internals (needs reconciler-assigned stable child LIDs — the natural bridge to the §7.4 "derive structure as a pure fn of on-log parent state" cure).
- **Reproduce:** `cargo test -p safer_v_proto` (6/6, `--test todomvc -- --nocapture` prints the replay log/dead-letter counts); `cargo run -p safer_v_proto --bin capture_todomvc` → `safer-v-todomvc-{0,1}.png`; `cargo run -p safer_v_proto --bin todomvc` (windowed). Surface: `examples/safer_v_proto/src/lib.rs`; app: `src/todomvc.rs`; tests: `tests/todomvc.rs`.

### 2026-07-01 — Wave 3: scaling — conditional view + child sub-components + async (the final wave)

- **Built (extends `lib.rs`, does not rewrite):** a `Kind::Empty` zero-paint slot placeholder + `Element::empty()` + a `when(cond, el)` conditional helper; `Element::map<Parent>(f: fn(Msg)->Parent)` (message-lifting, the Elm `Html.map`); `Empty` arms in `patch_node`/`spawn_node`; an `entities_of_kind` test helper. New app: `src/scaling.rs` — ONE `ScalingApp` model + `enum Msg` + pure `update` + one `view`, embedding the **real** `counter` twice as owned sub-state, a `when`-gated details panel, and a Load→result async flow. New bins `bin/{scaling,capture_scaling}`; tests `tests/scaling.rs`. Everything **compiles + RUNS**; nothing stubbed except async's *launch site* (forced out of `update` — see below).
- **Ran + VERIFIED MYSELF (not trusting green):**
  - `cargo test -p safer_v_proto` → **9/9** (3 W1 + 3 W2 + 3 W3). W3: conditional-siblings, child-lift-isolation, async-fold-back all pass.
  - `cargo run -p safer_v_proto --bin capture_scaling` → **4 GPU PNGs, VIEWED** (`safer-v-scaling-0..3.png`): (0) seed — two `Count: 0` children, both Resets dimmed (per-child `on_press_maybe` at 0), details hidden, `(idle — press Load)`; (1) after Show-details + left `+`×3 + right `+`×1 — **Left `Count: 3` / Right `Count: 1` INDEPENDENTLY** (message-lift proven in pixels), both Resets now bright, the details panel visible with **`Left + Right = 4`** (a live read of the *children's* sub-state), toggle now reads `Hide details`; (2) Load pressed — Load **dimmed**, status is the `Loading…` spinner; (3) result folded back — Load **re-enabled**, status slot **swapped `text`→`button`** to `Result: 42 rows … (Clear)`. The whole loop is in the pixels. (The `✓` glyph shows as tofu — the default font lacks U+2713; cosmetic only.)

- **(1) CONDITIONAL — kind-change-at-a-position reconciles WITHOUT sibling churn. HOLDS, with one design move.** The Wave-1 reconciler *already* swaps a child that changes `Kind` at a fixed index (`reconcile_node`: kind mismatch ⇒ despawn old + spawn new), and positional reconcile keeps the *other* indices in place — so `if cond { button(..) } else { text(..) }` (two different-kind branches at one slot) reconciles cleanly and its siblings keep identity. The trap is **present↔absent**: a bare `Option`/absent child *changes the child count*, which shifts every following sibling's index → positional churn (the W1 limitation). The fix is a one-liner design: **`when(cond, el)` renders an `Empty` placeholder instead of removing the child**, so hide/show is a `content↔Empty` kind-swap *at a stable index*. The test pins the title, the toggle button, and the (later-sibling) Load button, toggles the panel on/off twice, and asserts **all three keep their exact entity ids** while the slot alternates `Empty`(1)↔`Column`(0). **How the author spells it:** plain `if` for the two-branch case (natural Rust, zero new API); `when(cond, el)` for show/*hide* where there's no natural "else". Both read clean. **KEEP** — but the FINAL should make `when` the blessed spelling and document that a bare `Option<Element>` at a non-terminal slot churns (or auto-wrap `None` as `Empty` in the container so even `Option` is churn-free).

- **(2) CHILD SUB-COMPONENTS — message-lifting COMPOSES CLEANLY, and it's the right default (not the machine tier).** I embedded the real `counter` **twice** as **parent-owned sub-state** (`left`/`right` fields of the one `ScalingApp`), reusing `counter::view` + `counter::update` **verbatim**, and lifted each child view with `counter::view(&s.left).map(Msg::Left)`. The app stays Model+Msg+update+view with **zero** hand-wired routing/bind; each child folds onto its own field, fully isolated (test: left `+`×3 / right `+`×1 → `(3, 1)`; a left `-` never touches the right). **Ergonomics in Rust — better than feared:** `Msg::Left` *is* a `fn(counter::Msg) -> Msg` (a tuple-variant ctor), so `.map` takes a **bare fn pointer** — `Copy`, determinism-clean, no closure, no `Rc`/lifetime fight. The parent reducer delegates with one line: `counter::update(&mut s.left, cm)`.
  - **The two real frictions (report):** (a) **`.map` can't lift `on_input`.** `on_input` is a bare `fn(String)->Msg` and *cannot be composed* with `f` into a new bare `fn(String)->Parent` (that needs a closure), so a lifted subtree **drops `on_input`** (guarded by a `debug_assert`; harmless for a button-only child like Counter, but **lifting an input-bearing child needs a boxed `Fn` on the element** — the same residual V-cost W2 flagged, now confirmed as the blocker for general composition). (b) **No `Cmd::map`.** A child whose `update` returns a real `Cmd<ChildMsg>` can't have those effects re-tagged into the parent — the substrate `Cmd` has no `map`. Counter returns `Cmd::none()` so I drop it, but a child that *emitted* would need a local `map_cmd(child_cmd, Msg::Left)` the substrate should provide.
  - **`.map`-lifting vs child-entity-models (the machine tier):** the alternative is what `buiy_widgets::menu.rs` does — each child a *real `Model` on its own entity* (`MenuModel` + reducer + an early `MenuSet` chain + a `bind_menu_model` projection). That decouples the child but is **heavy** (a whole SystemSet chain + a projection bind per child) and, decisively, **fragments the state across entities** — which *breaks the W2 whole-UI single-model replay property* (each child model is its own on-log truth with its own LID; structural spawns are off-log). **Verdict for the FINAL: parent-owned sub-state + `.map` is the Elm/Iced-idiomatic default** (composes, replay-preserving, one `view`); **reserve the machine tier for widgets with genuinely independent lifecycles** (menus/dialogs/popovers with their own open/active/dismiss state + AT seams). **REFINE:** add `Cmd::map` to the substrate and decide the `on_input` lift story (a boxed/`Arc` `Fn` with a runtime purity check, or accept that input-bearing children can't be lifted).

- **(3) ASYNC `Cmd::task` — CONFIRMED ROADMAP GAP; the fold-back path itself is CLEAN.** Ground truth from `crates/buiy_core/src/mvu/mod.rs`: **`Cmd` is `None | Emit | Batch` only** — there is **no `task`/async variant** (spec §8 explicitly defers it; `Origin::Command` is *reserved* in the log format but never emitted in v1). So a pure `update` **cannot launch an effect** — the single sharpest DX gap this whole prototype found. I drove async the sanctioned way (the repo's own `system_scan.rs` idiom): `Msg::Load` just flips a `loading` flag; a hand-written `launch_load` system watches the flag rise and spawns a real `AsyncComputeTaskPool` task; `poll_load` `block_on(poll_once(..))`s it and **`enqueue`s the result back as `Msg::Loaded`** — which folds through the real funnel (recorded, `set_if_neq`, drain) exactly like any message. **The fold-back is clean and replay-shaped** (the result *is* a normal recorded `Msg`); **what's missing is the launch site** — the effect lives in two out-of-band systems instead of being returned as a value from `update`. **The FINAL must add `Cmd::task(future, |result| Msg)`** (and stamp its result `Origin::Command`, so replay re-plays the *recorded result* instead of re-running the non-deterministic effect — the reason `Origin::Command` was reserved). **REDESIGN (the biggest single item for Phase B).**
  - **Timing gotcha found by RUNNING (worth keeping):** a wall-clock "fake delay" is a *terrible* thing to assert a loading window against in a **heavy headless test** — each debug frame runs the full widget/layout/text stack (~100 ms), so `press()`'s 3 updates blew past even a 300 ms sleep and the task finished *before I looked* (first red). The robust fix is **structural, not timing**: fold the `Load` press with **exactly one `app.update()`** — on that frame the funnel flips `loading` in `Drain`, but `launch_load` (in the earlier `Enqueue` set) read the pre-fold `false`, so the task **provably hasn't spawned yet**. That observes the loading state race-free. (The GPU capture bumps the fake delay to 4 s and captures the spinner with the same single-update trick.)

- **Surprises / smaller notes:** (a) reusing a `#[derive(Model)]`/Component (`counter::Counter`) as a plain **field** of another model Just Works for `Reflect`/`Clone`/`PartialEq` — no friction embedding widgets-as-data. (b) The `Empty` slot is a genuinely tiny addition (one `Kind`, two one-line match arms) that closes a real correctness hole — a good sign the reconciler's shape is right. (c) `Query::single()` returns `Result` in 0.19 (the `let Ok(..) = q.single() else {..}` idiom), used in the async systems.

- **Verdict (W3 — closes the prototype):** all three scaling questions **hold on the surface**. Conditional + child-lift are **KEEP/REFINE** (small, idiomatic); the **one REDESIGN the FINAL must own is `Cmd::task`** (async as a value from `update`, replay-safe via `Origin::Command`), plus its two little siblings `Cmd::map` and a boxed-`Fn`/`Arc` `on_input` so message-lifting is *total*. The single-model `view(&Model)` shape **composes sub-components without fragmenting state** — which keeps W2's whole-UI-replay property intact through composition, the throughline of the whole prototype.

Surface additions: `examples/safer_v_proto/src/lib.rs` (`Kind::Empty`, `Element::empty`/`map`, `when`, `entities_of_kind`); app: `src/scaling.rs`; tests: `tests/scaling.rs`.
