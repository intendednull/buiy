## 0. What this is

A clean-room **re-implementation**, done right on current `main`, of the work a throwaway TodoMVC prototype explored — scoped up (by explicit decision, §2.1) from "a flat TodoMVC" into the kickoff of an **interactive widget-catalog subsystem**: real pointer/keyboard input, accessible stateful widgets, scroll/overlay/modal containers, F-tier styling, and a widget-gallery exemplar that exercises all of it.

The prototype itself is **not** the artifact — it lives on the unmerged `worktree-todomvc-prototype` branch and is on a superseded base (bevy 0.18 / accesskit 0.21 / pre-`buiy_bsn`). Its value is the bugs it surfaced and the seams it stressed. **Every fix is re-derived on current `main` (bevy 0.19.0-rc.3 / accesskit 0.24 / `#[require]`+scene-fn widgets), not cherry-picked.**

## 1. Executive summary

The audit confirmed all three prototype-surfaced `buiy_core` bugs are **real and live on `main`**, and that the picking bug is a coordinate-space *class* bug (a second latent instance lives in `render/clip.rs`), that the text-commit guard would *mask* the unfixed editor-content clobber (so they are one fix), and that keyboard focus is **structurally invisible** (a WCAG 2.4.7 failure). It also confirmed the campaign's direction (§2) **realizes the foundation** rather than inventing anything new: the foundation already commits the full `Pointer<E>` event taxonomy, separate aria-state semantics, and the F-tier styling channels; the current code is a Phase-0 stopgap that never matched those chapters.

The work decomposes into **nine child specs (C0–C8)** built in **six waves**, with verification (C7) pulled *early* as the regression gate, and the input rework (C3) as the linchpin everything interactive depends on. Under the co-drive (banner above), the **non-widget waves (C1/C2/C7) build in parallel with the tool substrate (P1a/P1b) from day one**, and the widget waves (C4/C5/C8) consume the substrate as it lands — see the coordination plan's wave plan for the interleaved order.

## 2. Decisions (decided — recorded with rationale + rejected runner-up)

Four were chosen by the user on 2026-06-22; two are evidence-driven defaults the user left me to take. Each names the runner-up and why it lost, per the project's "surface tradeoffs" rule.

### 2.1 Scope = widget-catalog subsystem kickoff *(user)*
Build a **widget-gallery exemplar** exercising scrolling/long-lists, overlays/menus, modal + focus-trap, and the full F-tier styling — with TodoMVC subsumed as one screen. **Why:** the prototype's stated purpose was "exploring gaps in our feature set"; a flat 2-row card exercises almost none of the catalog the foundation promises (no scroll, no overlays, no stacking-aware picking, no focus ring under real input). The gallery *is* the gap-finder. **Runner-up — "faithful flat TodoMVC, done right":** smaller and faithful to the literal prototype, but it would re-discover the same narrow slice and defer the very capabilities (overlay-aware picking depth, focus-trap, scroll) where the next real bugs hide. Rejected as under-ambitious for a *kickoff*.

### 2.2 Input model = adopt bevy_picking `Pointer<E>` taxonomy *(user)*
Replace the single-`Hovered`-resource poll with bevy_picking's `Pointer<Over/Move/Out/Press/Release/Click/Drag*/Scroll/Cancel>` events + observers + capture→target→bubble propagation + a real camera ref. **Why:** the foundation **already commits this** (`interaction.md §3.7`: full pointer/mouse/wheel taxonomy at F-tier, capture→target→bubble, `stopPropagation`/`preventDefault`) and the prior-art is explicit — `bevy-picking/lessons.md`: *"Buiy's widget contracts can directly reference `Pointer<E>`… don't invent a parallel event model."* The thin `Hovered` layer is the Phase-0 closeout stopgap, never the target. It also structurally fixes the composite-widget hit-bubbling wart and gives a home for double-click (edit-in-place) and drag (reorder). **Note:** bevy_picking 0.19 has **no `Pointer<DoubleClick>` event** (only a `count` on `Pointer<Click>`/`Press`), so the widget-agnostic double-click edit-in-place needs is a **Buiy-native `MultiClick` `EntityEvent`** owned by C3 (derived from the editor's `ClickTracker` heuristic, emitted on any picked entity — see C3 §2.11); it is not a bevy_picking event. **Runner-up — "keep the thin `Hovered` layer, extend minimally":** lowest blast radius, but it would entrench a stopgap the foundation already disowns and force a parallel event vocabulary the prior-art warns against. Rejected.

### 2.3 Widget state = separate components lowered into a11y *(user)* — **superseded by §2.7**
> **Superseded by §2.7 (coordinate-with-agent-interface).** Do **not** define separate `Checked`/`Pressed` components owned by `buiy_widgets`. Adopt the agent-interface campaign's decomposed `A11yToggled` (tri-state, incl. `Mixed`, role-disambiguated) + `A11ySelected`/`A11yExpanded` from `a11y/states.rs`. The original decision below is retained for the audit trail — it correctly rejected the prototype's `A11yToggled(bool)` conflation, and the agent-interface campaign's **tri-state `A11yToggled`** (Checkbox carries it incl. `Mixed`; Switch binary; Button role disambiguates pressed-vs-checked) is exactly that fix, landed in the a11y substrate rather than as a parallel `buiy_widgets` component.

The framework owns separate widget-state components — a tri-state `ToggleState{Off,On,Mixed}` plus `Checked`/`Pressed`/`Selected`/`InteractionDisabled` — lowered **one-way** into the a11y layer; `translate.rs` disambiguates `aria-checked` vs `aria-pressed` by role. (Crate placement — the *types* in `buiy_core` next to `A11yRole` so lowering+verify co-locate, the widget *markers/behavior* in `buiy_widgets` — is fixed in §7.) **Why:** the prototype's `A11yToggled(bool)` conflated `aria-checked` with `aria-pressed`, was structurally incapable of the tri-state `Mixed` the foundation *already commits* (`accessibility.md`), and is not `bsn!`-authorable (`(Checkbox, A11yToggled(true))` is a duplicate-component panic). Separate state components are the `bevy_ui_widgets` pattern (`Checked`/`Pressed`/`InteractionDisabled`), `bsn!`-native (absence == default, no panic), and keep app-logic state off an a11y-named type. **Runner-ups:** *(b)* a single role-neutral `ToggleState` the a11y layer reads — elegant single-source-of-truth, but couples every toggle to one enum and needs role-branching anyway; *(c)* widen `A11yToggled` to an enum — smallest change, but keeps the checked/pressed conflation and the a11y-named-type coupling. Both rejected for layering. *(Tri-state is carried by the `ToggleState` enum; `Selected` stays a bool to match the accesskit asymmetry.)*

### 2.4 Styling = feed the full F-tier now *(user)*
Wire `BoxShadow` / per-side `Border` / `Outline` (+ the focus ring) into the live `extract→pack→bucket→specialize→draw` spine. **Why:** the foundation commits these at F-tier (`visuals.md §3.3`), the `shadow.wgsl` shader and `Shadow` primitive *already exist but are unfed*, and the broader scope (cards with elevation, real borders, visible focus rings) needs them. It also forces reconciliation of the render-pipeline spec's **overstated status note** (it claims these "landed/verified" while the extract path doesn't paint them). **Runner-up — "flat-subset v1, defer shadows/borders/outlines":** sufficient for a flat TodoMVC and lower render risk, but incompatible with the chosen gallery scope and leaves the focus-ring (a WCAG blocker) unbuilt. Rejected as inconsistent with §2.1.

### 2.5 Coordinate space = layout-local `ResolvedLayout` + absolute consumers via `GlobalTransform` *(default)*
Keep `ResolvedLayout.position` parent-**local**; route every absolute consumer (picking, `clip.rs`, overlays, outline ink-bounds) through `GlobalTransform`, made **non-optional** (drop the prototype's `unwrap_or(layout.position)` fallback that silently mixed spaces); fix the lying `components.rs:65` "window-relative" doc comment. **Why:** the audit's adversarial pass found making `.position` absolute would **break the transform bridge** (`bridge.rs:138` computes `base = position − acc`, assuming a relative position — an absolute value double-corrects and breaks the scroll→`GlobalTransform` fold). **Runner-up — "make `ResolvedLayout.position` absolute via accumulation":** one honest field for all consumers, but large blast radius (every layout golden re-blessed; sticky/scroll/anchor interactions) **and** it breaks the bridge. Rejected on the bridge evidence.

### 2.6 Editor text integrity = fix Bug 2 + Bug 3 together, preedit-aware *(default)*
The `text_commit` shape-guard (Bug 2) and the `TextSync` editor-content clobber (Bug 3) are **one** change, not two. **Why:** on the editor class the `FontsGeneration` sweep *clobbers* typed content (`set_text("")` onto the editor-owned buffer); the commit guard then reshapes the now-empty buffer and **silences the assert while the user's text is gone**. Fixing only the guard ships a framework that silently eats editor content on any async font load. The fix must also preserve a live IME **preedit** (a mid-composition `set_text` destroys composition) and the editor's only style/seed channel. Exact shape (content/style split vs edge-triggered value-diff) is a C2 open question; the *joint, preedit-aware* framing is decided.

### 2.7 Relationship to the agent-interface campaign — coordinate, don't cede *(user, 2026-06-22)*

The **agent-interface campaign** (`docs/specs/2026-06-18-buiy-agent-interface-design/`; Phase 0 landed on `main` via PR #79 @ `a1ab149`) is **LOCKED (#5)** to own the accessibility substrate: decomposed `A11yStates`/`A11yRelations` (`a11y/states.rs`), the `A11yRole` enum, ACCNAME 1.2, real ECS-tree nesting, the **inbound action router** (`route_action_requests` over the existing `bevy_winit` `ActionRequestWrapper`), the **in-process driver** (`a11y/inprocess.rs`), per-widget **WAI-ARIA APG contracts** (`A11yContract`), the **canonical APG widget bundles** in `buiy_widgets` (P1d: Checkbox/Switch/Slider/Disclosure/Dialog/Tooltip/TextInput), and the a11y gates **#3/#4/#6/#7/#12**. It explicitly *supersedes* the `buiy-accessibility-design` slot.

This campaign's specs (C1–C8) were authored on `507855f`, **before #79 merged**, blind to it — the root of the overlap. **By decision (2026-06-22): this campaign COORDINATES with — does not duplicate or cede to — the agent-interface campaign.** It keeps its full scope, but rebuilds every a11y/widget decision *on* the agent-interface substrate and supplies the geometry/render/input/scroll/styling/exemplar layer the agent-interface widgets need but the agent-interface campaign does not build.

**Division of labor**

**This section supersedes**: §2.3's separate `Checked`/`Pressed` (use `A11yToggled`-tristate + `A11ySelected`); the §3/§6/§7 lines that put the a11y substrate / roles / wire-format / `Activate` under C4/C7 (the substrate is **realized by the agent-interface campaign**; C4/C7 *consume* it); and it re-bases the §8 gate on the agent-interface **P1a** (states) + **P1c** (router/driver) + **P1d** (widgets) landing. ## 5. Sequencing (six waves)

Everything is **spec'able now in parallel** (once C0 anchors the children). **Code** lands wave-by-wave only after the implementation gate (§8).

- **Wave 0 — C0** (spec only): README + realizes/supersedes maps + the `docs/README` catalog entry must exist before the facet children (README-before-facets).
- **Wave 1 — C1 + C2 + C7** (foundational correctness + the gate): C1 and C2 are independent, lowest blast radius. **C7's Tier-A harness + Tier-B land here, RED-first** — Tier A is the regression gate that proves C1 (revert C1 → Tier A RED on an offset widget); Tier B is C2's content-survival gate. This is why C7 depends only on C0+C1: it must exist as the gate *for* C1/C3, not after them.
- **Wave 2 — C3** (the linchpin): gated hard behind C1 (non-optional `GlobalTransform`) and C7's Tier-A (every consumer migration off `just_pressed(Hovered)` — ~18 hand-set-`Hovered` test files + `button.rs` + `text_*.rs` — needs the real-input tier to stay CI-green). Also lands the `painters_z` pick-depth primitive C5 reuses. Delete `Hovered` last behind a shim.
- **Wave 3 — C4 + C6** (parallel, disjoint code: a11y+widgets vs render/extract). C4's focus-visible state + state components feed C6's focus-ring lowering + per-state styling; sequence C4's lowering slightly ahead, bulk overlaps. C6 must not bump the 68B quad stride.

## 6. Cross-cutting arbitration (resolved here so children don't re-litigate)

1. **Pick-depth from `painters_z`** is needed by C3 (overlay/menu/modal hit-correctness: pick-order == paint-order) **and** C5 (light-dismiss/interception). **Owner = C3** (it rewrites `emit_picks`); C5 consumes. 3. **`Pointer<Scroll>`**: C3 owns the event **entry**; C5 owns nearest-container routing + clamp + overscroll. The thin-MouseWheel fallback is moot under §2.2.

9. **Event vocabulary**: **NO competing `Activate` event** (§2.7). Activation routes through the existing **`OnPress`** message and the **agent-interface action router** — the router lowers an inbound `Action::Click` (`ActionRequest { action: Action::Click, .. }`) into the SAME `OnPress` sink the pointer/keyboard paths emit (action-router §4; **accesskit 0.24 has NO `Action::Default`** — the activation action is `Action::Click`).
