# Buiy — App-Author Ergonomics: Learnings

*Synthesized from six dogfooding campaigns: MVU/state, buiy_view, BSN/decomposed-components, widget/gallery parity, the Dooduel full-app build, LLM/agent DX, and web/mobile.*

## 1. The through-line

Buiy's *core* authoring bets are sound and durable: a pure Model+Msg+reducer, a pure `view(&Model)->Element` surface, and `#[require]`-materialized decomposed components all held up from a counter to a whole real-time game. The recurring cost is **not** architectural — every framework gap the campaigns hit was *additive* (a missing modifier, a missing primitive, a missing accessor) — it is that too many failures are **silent**: the model folds but the rows don't replay, the label spawns but never paints, the transparent box swallows every click, the theme token typechecks and ships magenta. The single strongest cross-cutting signal is that **headless-green and typechecks-clean are both unreliable proxies for "works"** — the render world, the live pick path, and the browser conformance lane are all structurally blind spots that only running the artifact exposes.

## 2. What works well (wins)

- **The pure Model+Msg+reducer core is the piece every source says "do not touch."** `mvu_model(reduce)` compiles first-try and scales from an `i64` to a ~10-arm whole-game reducer with no strain; all state logic is one pure, GPU-free-testable function, and `set_if_neq` drain discipline makes flicker impossible by construction (idempotent re-folds are free no-ops). *(MVU; full-app §2)*
- **"It's just Rust" views + uniform dot-method builders paid off.** Every knob chains (`.gap()/.on_press()/.grow()`), control flow is host Rust (`.iter().map()`, `if`/`match`), so a wrong view is a wrong ordinary expression with precise rustc spans instead of proc-macro soup — and the near-isomorphism to Iced means LLMs reproduce it from strong priors. Unanimous 6-0 in the LLM panel. *(view)*
- **A bare marker + `#[require]` materializes the whole widget from one identifier.** `bsn! { Button }` pulls `Node` (→ the full 14-component Style decomposition), `Focusable`, roles, labels, canonical box/background — authoring cost scales with what you *override*, not the widget's full contract. *(BSN)*
- **One canonical semantic (AccessKit) tree serves screen readers, the test driver, and LLM agents at once.** Agent-legibility rides on accessibility work already being done — there is no separate "agent API" to keep in sync — and a GPU-free `snapshot_report` text tree gives a sightless agent full "eyes" at ~2–5 KB vs >1000 vision tokens. *(agent DX)*
- **The whole skribbl-clone builds on Buiy today.** Native + web-desktop + web-mobile, drawing canvas, real-time loop, theming, persistence — the W0 skeleton compiled *and passed its probe first try off nothing but front-door AGENTS.md docs*. Documented patterns being accurate on first use is the load-bearing signal the API surface is honest. *(full-app §1)*
- **The render spine is factored for extension; the ONE net-new subsystem was mechanical.** Adding a whole new sampled primitive (`RasterImage`) was pure precedent-mirroring (instance record + SpecializedRenderPipeline + specialize + draw section), leaving the closed primitive enum and byte-stable quad path untouched. *(full-app §2)*
- **"Write once" genuinely holds at the app-logic layer.** Nothing in widget/MVU/layout surface changes per-platform; every web change is `cfg(wasm32)`-gated or a new build target, and native vs `gallery_web` differ *only* in window/canvas setup with zero screen-logic duplication. *(web)*

## 3. Friction points

- **The missing declarative View was the dominant app-author cost (now largely fixed by buiy_view).** MVU-as-core shipped as "M-U + manual bind": hand-writing `Query<&Model, Changed>` field projection *exploded* at list scale — a ~60-line exclusive `&mut World` keyed reconcile where Elm/Iced spend ~5 lines. This directly motivated `keyed_column`, which by the Dooduel app "solved scoreboard/chat/word-picker for free." *(MVU → view)*
- **No scroll container is the #1 missing view primitive.** It forced a cap-to-12-messages chat hack and constrained mobile single-column layout; `scroll_column` + auto-scroll-to-bottom is the top request. *(full-app §5)*
- **The view sizing surface accreted ad-hoc, one modifier per wave.** `.width→.fill→.grow→.shrink→.justify_*→.top_layer→.fixed→.ignore_picking`, and still misses flex-wrap, per-side padding, text-align, and inset/absolute — all four hit real work and all four were worked around app-side. The altitude is right; the recommendation is to design the coherent surface in *one* pass. *(full-app §5)*
- **Enum-variant / Option / Vec components need the verbose `template_value(...)` escape, and one intent must be co-spelled across components.** Fieldless variants (`Display::flex_column()`, `A11yRole::TextInput`) can't be field-patched, and a flex column requires *both* `template_value(Display::flex_column())` *and* a matching `FlexParams { direction }` kept in sync by hand — clean concern boundaries, but coordination pushed onto the author. *(BSN)*
- **Reading widget state through a foreign accesskit enum instead of a domain accessor.** Before the domain-accessor pass, `checked` lived on `A11yToggled(Toggled::True)` — never in training data — so agents fabricated `checkbox.checked`. Types are the entire discovery mechanism when there are no examples. *(agent DX; since fixed with `Checkbox::checked()` etc.)*
- **Broad browser reach is a two-artifact build + JS loader, and shipping wasm is its own release phase.** WebGPU is default-off in Firefox, so you ship two wasm builds + a `navigator.gpu` feature-detect loader; debug wasm (~114 MB) exceeds the Pages 100 MB ceiling, and `trunk` auto-runs `wasm-opt` as a bare `-O` → fatal abort. A real packaging phase distinct from `cargo build`. *(web)*

## 4. Gotchas that bite (the silent, expensive ones)

### ⚠️ CROSS-CUTTING (seen in 3+ areas) — the strongest signals

- **"Invisible pickable box swallows all clicks" — at least the THIRD appearance in project history.** A transparent, full-window `.top_layer()`/`.fixed()` container sits topmost in pick order; picking truncates at the first occluder, so the whole app goes click-dead while painting nothing. Invisible to *every* prior gate because a11y `Action::Click` bypasses pick occlusion and GPU screenshots don't pick at all — only a real synthetic-pointer click over the real hit-test exposes it. **Mechanism: pick-set ≠ paint-set.** Seen in widget/gallery (detached modal Dialog), full-app (theme toggle), and designed against in view (`.top_layer()` auto-click-through + `.ignore_picking()`). *(widget, full-app, view)*
- **Headless-green ≠ works — the render world and live frame loop are an untested blind spot.** MinimalPlugins + single `app.update()` never instantiates the render world or runs the frame loop, so three whole bug classes are structurally invisible: crashes at render-extract (unshaped editor buffer), invisible content (labels that never lay out), and total non-interactivity. *Worse, headless layout snapshots BAKE IN the broken state* — missing labels were encoded as `size=0` goldens and stayed green forever. Three separate first-time live-runs each caught a class the whole green suite missed. **Always run the actual GUI before calling widget/gallery/app work done.** *(widget, full-app, web)*
- **Fail-silent is the dominant failure *shape* across every area.** A model without a unique `LogicalId` dead-letters ALL its folds with no error (view); a stringly theme token ships magenta *or* silently drops the styled feature to reach green (agent); AT `set_value` never emits `TextChanged` so submits arrive empty (full-app); web clipboard/IME/a11y build a correct tree that reaches zero AT (web). The common lesson: **"nothing happens and no error" is the worst diagnostic experience** — fail loud in dev/test, degrade only in release, and route the signal to the channel the loop actually reads. *(view, agent, full-app, web)*

### Area-specific sharp edges

- **A bare `Text` node silently never lays out, shapes, or paints.** The whole pipeline only acts on layout nodes, so `Text` on a non-`Node` entity gets a correct accessible name and paints *absolutely nothing* — it blanked every gallery label while the a11y tree looked healthy. Fixed structurally with `#[require(Node)]`. The agent-DX twin: role-less `Text` is invisible to the semantic tree, so it doesn't exist on the agent's only channel. *(widget, agent)*
- **Record/replay silently does NOT cover structural (add/remove) state.** Replay covers only funneled folds; imperative spawn/despawn done *downstream* of the reducer (keyed-reconcile bind) is off-log, so a real TodoMVC works live but is not replay-safe for add/remove — THE case for any list app. buiy_view sidesteps this by making rows pure derived view rebuilt from a single on-log model. *(MVU → view)*
- **Global-tier paint order: a top-layer modal can't occlude base text/icons/borders (the "transparent scrim").** Buiy draws in fixed global tiers (shadow < quad+raster < glyph < icon < band), not per-stacking-context, so a scrim quad dims base quads but glyphs/icons/borders draw in *later* tiers over it and bleed through undimmed — a modal reads as "no scrim." Forced the avatar editor to a full in-flow screen. Root-caused via real-app GPU capture, not goldens. *(full-app; later fixed by a deep refactor)*
- **Single-field-patching a `#[require]`d component silently drops the widget's other defaults (§4.1c).** Required-components fill only when *missing*, so `bsn! { Button BoxModel { width } }` starts from `BoxModel::default()` (padding 0), suppressing the canonical initializer — spawns and renders, just wrong. **Always route styled authoring through the scene-fn.** *(BSN)*
- **Behavioral no-ops: visuals wired only at spawn, no runtime reflect-on-`Changed`.** A click flips state but paint stays frozen because the styling fn ran only in `build_*()`; the state assertion passes, the pixels are wrong — invisible to any headless test that asserts internal state. *(widget)*
- **Cold-tap / one-frame hover lag breaks touch and synthetic clicks.** A press with no prior settled hover misses the target; a real desktop mouse always hovers first, so it's invisible in desktop dev and produced a false "web gallery is non-interactive" conclusion. Drive synthetic input as move→settle→click. *(web)*
- **`.fill()` vs `.grow()` and "just return `None`" are easy wrong turns.** `.fill()` is 100%-of-containing-block (overflows under flex-shrink) vs `.grow()` = remaining free space; returning `None`/omitting a child shifts every following sibling's positional index and churns their identity — use the stable-slot `when(cond, el)` `Empty` placeholder. *(view)*
- **AT `set_value` doesn't fold into the MVU model; controlled inputs get clobbered on per-frame-rebuilding screens.** The accessibility act-then-observe seam is a known unfunnelable seam; a controlled `text_input` on a re-rendered screen re-clobbers the un-folded value each tick, and `on_submit_with` is unsafe under a ticking model (wipes in-progress typing). *(full-app, MVU)*
- **`WinitSettings::mobile()` is the wrong setting — its name matches the target.** It pins a 60fps idle loop (battery drain); `desktop_app()` reactive mode cuts idle ~140x — and even then a sleeping reactive loop won't wake on a non-winit model change without an `EventLoopProxy` wake-bridge. *(mobile)*
- **The native GPU lane is permanently blind to browser shader conformance.** WGSL derivative builtins after an early clip-discard pass native naga but fail Chrome's Tint uniformity rule → blank screen while the native GPU lane stays green forever. You MUST run the artifact in a real browser. *(web)*

## 5. Patterns that work (idioms to reach for)

- **Single-model `view(&Model)` + parent-owned sub-state → whole-UI replay is a property of the model alone.** Compose with `Element::map(ParentMsg::Child)` and hold child state as a *field* of the one model; reserve the heavier machine tier (child models on their own entities) only for genuinely independent lifecycles. Sidesteps the keyed-list-replay wall. *(view, full-app)*
- **`keyed_column(iter, key_fn, view_fn)` makes the reconciliation key a REQUIRED positional arg.** Illegal-states-unrepresentable: the forgotten-`.key()` footgun (compiles clean, silently corrupts identity) is designed out. The canonical "steal the safety, keep the ergonomics" move for any optional-but-load-bearing knob. *(view)*
- **Poll-clock-as-Msg (`Tick(now)`), never edge-triggered `Cmd::interval`.** Enqueue a tick every frame and DERIVE everything from `now − anchor`, storing only derived values (never raw `now`, re-anchor each tick) → replayable, idempotent, `set_if_neq`-perf-free. The Dooduel prototype specifically proved the wished-for edge-triggered timer is the *wrong* shape (hard to replay, hard to keep clean). *(MVU, full-app)*
- **Rising-edge side-effect observer for decoupled ECS surfaces.** Drive confetti, per-turn canvas clear, theme sync, persistence from model edges via a `Local`-latch that READS the model and never enqueues back; project model→side-surface one-way with imperative ops riding monotonic `*_seq` counters drained once. *(MVU, full-app)*
- **`fold_one_inline` is the strangler-migration primitive.** Route an *existing* exclusive `&mut World` applier through an MVU model in place — keeping its schedule slot and exact behavior — instead of rewiring the full enqueue→drain→bind machine. Made a 10k-line app's screen router MVU-migration regression-free. *(MVU)*
- **Pure `Game` core + thin MVU reducer for the game/app phase machine.** A framework-decoupled `Game` struct (every rule a `&mut self` method, unit-testable with no ECS/GPU/clock) behind a ~10-arm reducer replaced `bevy_state` cleanly. *(full-app)*
- **CPU-authoritative buffer + keyed Resource for side surfaces the framework can't fold.** Canvas pixels live in a keyed `PaintCanvases` *Resource* (not a component — the reconciler despawns/respawns the node on screen-swap and a component would lose them); CPU-side buffer beats a GPU render-target because flood-fill reads pixels and undo/serialize want it CPU-side anyway. *(full-app)*
- **Labelled controls = flex-rows of pick-through siblings, sized to content.** Put the control box on one child, the label beside it as a pick-through sibling so clicking the row toggles; content-width with a centered label child, never a fixed 120px box. *(widget)*
- **"The example IS the fixture" + a live-interaction test tier.** Stand up the *same* plugin set the binary boots over a synthetic window, resolve each widget's real rect, inject synthetic move→press→release through the LIVE pick path, assert the observable state change — faithfulness proven by revert (15/16 fail with the fix reverted). Real OS pointer input (xdotool) beats event injection, which bypasses winit and masks the bug. *(widget)*
- **One source of truth via `{ rust_expr }` interpolation.** Reuse the same private initializer fns (`button_box_model()`) inside both the `#[require]` defaults and the scene-fn `bsn!` field-patches so the ECS-spawn and BSN paths can't drift. *(BSN)*
- **The prelude-only agent writes the target API — use it as design source *and* acceptance rig.** A fresh agent given only the prelude hallucinates exactly the prior-matching API you should build (`.checked(true)`, `ColorToken::Surface`, `.with_children`); diffing its guesses against reality is a cheap, repeatable eval. Token/missing-symbol failures are deterministic (close first); fluent spellings are probabilistic. *(agent DX)*
- **Emulate the mobile GLES / WebGL2 hardware floor on desktop.** `WgpuSettings::constrained_limits{max_vertex_attributes:16}` clamps a desktop GPU (RADV 32→16) so a mobile/WebGL2-only reach regression (an over-limit pipeline blanks the whole pass) surfaces in a normal desktop test run; a const guard makes a future 17th attribute re-break loudly. *(mobile, web)*

## 6. Recommendations (ranked by leverage)

1. **Move the fail-silent cases loud — this is the highest-leverage theme.** Make a missing/duplicate model `LogicalId` a loud error not a dead-letter; keep the closed-enum `ColorToken` + compiler-enforced `ThemeContract` (converts magenta + silent-feature-drop into E0004/E0599); emit `TextChanged` on AT `set_value`; surface web clipboard/IME/a11y inertness. General rule: fail-loud in dev/test, degrade in release, per-operation (warn-once dedup is invisible to an agent that sees one run), on the compile/startup/panic/stdout channel the loop reads. *(view, agent, full-app, web)*
2. **Make render-world invariants headless-reachable with a `Last`-scheduled coherence assert.** Mirror each render-extract invariant as a cheap debug-only main-world `Last` assertion that runs in every frame-pumping test — it red-flagged 26 tests and pinned the unshaped-buffer crash with no render world. Pair with a native-pointer live-interaction tier on the DEFAULT lane and CI the GPU lane incrementally (a PR-only GPU lane hid a real regression until merge). *(widget)*
3. **Design the coherent view layout surface in ONE pass — starting with a scroll container.** `scroll_column` + auto-scroll-to-bottom is the top ask; add flex-wrap, per-side padding, text-align, inset/absolute together rather than one modifier per wave. *(full-app, view)*
4. **Auto-`Pickable::IGNORE` transparent top-layer containers + make pick-set == paint-set the enforced default.** The invisible-click-swallower is now on its 3rd+ appearance; make the bug class unwritable by construction rather than caught by a test. *(full-app, widget, view)*
5. **Ship the app-author guidance that closes first-contact walls.** A task-oriented `using-mvu` guide, a documented headless logic-plugin set + a "drive my MVU feature in a unit test" builder ("which plugins?" is currently discovered by crash), and a self-sufficient curated prelude (essentials + collision resolution) — the near-invisible-to-humans, highest-yield fix for LLM authors. *(MVU, agent DX)*
6. **Close the remaining MVU/view composition gaps.** `on_submit_with(fn(String)->Msg)` (kill the two-message input round-trip), a reusable `ClockPlugin<M>` (every app re-hand-rolls the ~6-line tick driver), a runtime-owned `:active`/hover interaction layer outside the pure model, a story for composing a leaf-widget's state into an app model, and an MVU-side `SetValue` to clear a text field. *(MVU, view, full-app)*
7. **Surface the §4.1c required-component suppression at compile/lint time**, and project widget state through domain-native accessors (`Slider::value`, `Disclosure::expanded`) with the accesskit enum kept un-preluded — until then the enforceable rule is "a scene-fn for every styleable widget; direct-marker field-patching is unsupported." *(BSN, agent DX)*
