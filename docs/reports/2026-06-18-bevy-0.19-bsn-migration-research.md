# Bevy 0.19-rc migration + BSN integration — research findings

**Date:** 2026-06-18
**Status:** landed
**Verdict:** Feasibility confirmed and partially in flight; the bump is tractable (render graph removed → systems-in-`Core2d`, wgpu 27→29 mostly Bevy-masked, accesskit one field) and BSN authoring is compile-time / reflection-free.

> Spec and plan have since been written under their final names: [`docs/specs/2026-06-18-buiy-bsn-integration-design.md`](../specs/2026-06-18-buiy-bsn-integration-design.md) and [`docs/plans/2026-06-18-bevy-0.19-bsn-migration.md`](../plans/2026-06-18-bevy-0.19-bsn-migration.md). The "bevy-0.19-bsn-design.md" working name used in § 9 below predates them; treat this report as the immutable research snapshot.

Research input for the BSN integration spec and migration plan.
Inventories the Bevy 0.18.1 → 0.19.0-rc.3 bump (render graph, wgpu 27 → 29,
accesskit, ECS/reflect) and the BSN (`bsn!`) authoring surface, and maps both
onto Buiy's `crates/buiy_core` codebase by `file:line`. Audience: Buiy
maintainers and the author of the migration spec/plan. Version numbers,
`file:line` citations, and old→new API specifics are the load-bearing content —
preserve them through any later editing.

## 1. Executive summary

**Feasibility: confirmed and already partially in flight.** The bump is real and
tractable. The target worktree already pins `bevy = "0.19.0-rc.3"` with the
`bevy_scene` feature added, `Cargo.lock` already resolves the full new dependency
set (wgpu 29.0.3, naga 29.0.3, accesskit 0.24.1, winit 0.30.13), and
`cargo check -p buiy_core` already compiles far enough to surface the first wave
of real breakage. This is not speculation — the compiler output is authoritative
evidence.

**Blast radius (by subsystem, largest first):**

1. **Render-graph rewrite (Bevy core).** Bevy 0.19 removes the `RenderGraph`
   `Node`/`ViewNode` API; passes are now systems. Buiy's `render/node.rs` (the
   entire `ViewNode` impl + graph wiring) must be rewritten as systems scheduled
   into `Core2d`/`Core2dSystems`. This is the single biggest change and is
   compiler-confirmed broken.
2. **wgpu 27 → 29 render-pipeline churn.** Required field additions
   (`RenderPassDescriptor.multiview_mask`, `PipelineLayoutDescriptor.immediate_size`),
   sampler type changes, mapped-write semantics, `poll`/`PollType`. Mostly in
   `render/node.rs`, `atlas/gpu.rs`, `golden.rs`. Many sites are *masked* by Bevy
   wrapper types — must be triaged raw-wgpu vs. Bevy-wrapper.
3. **Resources-as-Components + ECS renames (Bevy core).** `Replace` → `Discard`
   lifecycle hook (compiler-confirmed broken at `layout/mod.rs:109`), non-send
   accessor renames, `Mutability = Mutable` bounds.
4. **BSN crate build.** Net-new `buiy_bsn` crate; low risk because BSN authoring
   is compile-time, no reflection/registry needed.
5. **a11y: one struct field.** `TreeUpdate` gains a required `tree_id` field — a
   single one-line edit. The headline accesskit/winit scares do not apply to Buiy.

**Biggest risks:**

- **R1 — Render-graph-as-systems rewrite** (`node.rs`): largest semantic change;
  must preserve exact pass ordering and the effect-compositor nesting. GPU-only
  verification.
- **R2 — wgpu raw-vs-masked ambiguity**: until grepped, unknown how many wgpu
  field changes Buiy must make vs. Bevy absorbs. Resolve by inspecting raw
  `wgpu::` descriptor literals first.
- **R3 — bevy_winit `ACCESS_KIT_ADAPTERS` re-export survival**: Buiy's a11y bridge
  depends on a bevy_winit implementation detail (thread-local path + stored
  `Adapter` type). accesskit_winit's multi-tree restructure landed in this window;
  the re-export could have moved. Highest-uncertainty a11y item.
- **R4 — GPU-only blast surface**: items 3–5 of wgpu (`poll`, `write_texture`,
  render-pass fields) won't appear on the headless gate; they only fail on the
  `#[ignore]` GPU lane. Must run the GPU lane to verify.

**Recommended phasing (high level):** deps already pinned → drive `cargo check`
green (imports/renames) → headless test gate green → GPU lane green → build
`buiy_bsn` crate (re-exports, component-template conformance) → real `bsn!` +
example → docs (spec + plan + follow-ups + README). Detail in §9.

## 3. Bevy core / ECS / reflect / render-graph breaking changes

Target: `0.19.0-rc.3`. Migration guide verified verbatim against the bevy-website
source. PR numbers in parens. **(R)** flags reflection-registration relevance.

### Compiler-confirmed (already failing in the worktree)

- **`bevy::ecs::lifecycle::Replace` → `Discard`** (`on_replace` → `on_discard`,
  `#[component(on_replace=…)]` → `on_discard`) (PR 22789). Broken at
  `layout/mod.rs:109`; 6 observer sites total across `layout/mod.rs` +
  `layout/systems.rs` (`Insert`/`Replace`/`Remove` × 2 files).
- **`bevy::render::render_graph` path removed** — `node.rs:26`. See
  render-graph section below.
- **`bevy::core_pipeline::core_2d::graph` relocation** — `node.rs:22`.

### bevy_ecs — Resources-as-Components (PRs 20934, 22910, 22911, 22919, 22930, 24424)

| Old | New | Action |
|---|---|---|
| `#[derive(Component, Resource)]` on one type | `Resource` is a subtrait of `Component`; can't be both | Split into two types if any Buiy type is both. |
| `#[reflect(Resource)]` reflected `ReflectResource` data | `ReflectResource` is a **ZST marker**; `#[reflect(Resource)]` *also* reflects `Component` | **(R)** Reflection-driven resource reads must use `ReflectComponent`, not `ReflectResource`. Surfaces in BRP/serialization. Buiy has 5× `#[reflect(Resource)]` — audit any reflective read-back. |
| Broad queries (`Query<()>`, `Query<EntityMut>`, `Query<Option<&T>>`) never saw resources | now see resource entities | Add `Without<IsResource>` filter if a broad query conflicts with resource access. |
| `init/insert_non_send_resource`, `World::non_send_resource[_mut]`, `get_non_send_resource[_mut]` | drop the `_resource` suffix (`init_non_send`, `non_send[_mut]`, …) | Rename (deprecated alias one release). |
| `ResMut<R>`/`World::resource_mut` for any `R: Resource` | require `R: Resource<Mutability = Mutable>` | Add bound in generic resource code, or `World::modify_resource`. |
| `Components::resource_id`/`register_resource[_with]`/`ComponentDescriptor::new_resource`; `Access::*_resource[s]*` family | unified component-access names; `Access` `*_resources` variants **removed** | Rename / replace; `Access` resource-suffixed methods are gone (not deprecated). |
| `World::clear_entities()` left resources | now clears resources too; `remove_resource_by_id` → `bool`; new `clear_all` | Audit `clear_entities`; adapt `bool` return. |
| `#[derive(Resource, MapEntities)]` | `MapEntities` default for components | Drop from resource derives. |

### bevy_ecs — schedules / systems / commands / observers

| Old | New | Action |
|---|---|---|

### bevy_reflect **(R)**

| Old | New | Action |
|---|---|---|
| `bevy_reflect::{Struct, DynamicStruct, StructInfo, FieldIter, …}` at root | moved into `structs`/`enums`/`list`/`map`/`set`/`array`/`tuple`/`tuple_struct` modules | Fix `use` paths (PR 22342). |
| `DynamicStruct::index_of`; `FieldIter` yields `&dyn PartialReflect` | `Struct::index_of_name`; `FieldIter` yields `(&str, &dyn PartialReflect)` | Update inspector/dynamic-struct traversal (PR 22708). |
| `Interned<T>` needed only `PartialEq/Eq/Hash` | requires `T: Internable` | Impl `Internable` for interned + reflected types (PR 22472). |

**Reflect derives unchanged.** No rename to
`Reflect`/`FromReflect`/`TypePath`/`ReflectComponent`/`ReflectDefault` or
`#[reflect(...)]` grammar (except the Resource → Component semantic above).
`register_type::<T>()` signature/behavior unchanged. **Buiy's 124 `register_type`
calls and 144 `#[derive(Reflect)]` sites do not break from the bump** — but see
the §6/§3 note: **`bsn!` does NOT need reflection at all** (registration only
matters for the old serialization path, BRP, or inspectors).

### Render-graph / RenderApp plumbing (largest core change)

> **VERIFIED against the vendored `bevy 0.19.0-rc.3` source on disk** (stated as
> fact, not speculation). The old `RenderGraph` `Node`/`ViewNode` API is
> **REMOVED**: there is **no `bevy::render::render_graph` module**, and
> `add_render_graph_node` / `add_render_graph_edges` are gone. `RenderGraph` is
> now a **render-world SCHEDULE** driven by
> `RenderGraphSystems::{Begin, Render, Submit, Finish}`. Passes are plain
> **systems** added to the `Core2d` schedule. The canonical signature, copied
> from `bevy_core_pipeline` 0.19 `main_transparent_pass_2d`:
>
> ```rust
> pub fn pass(
>     world: &World,
>     view: ViewQuery<(&ExtractedCamera, &ExtractedView, &ViewTarget, /* … */)>,
>     // … other SystemParams …
>     mut ctx: RenderContext,
> ) { /* … */ }
> ```
>
> — `RenderContext` is now a **SystemParam** (not a `&mut` argument). `ViewQuery`
> supplies per-view data. Build a pass body with
> `ctx.begin_tracked_render_pass(RenderPassDescriptor { /* … */, multiview_mask: None })`.
> Registration:
> `render_app.add_systems(Core2d, pass.in_set(Core2dSystems::PostProcess))`,
> with `.before()` / `.after()` replacing the old graph edges. `Core2dSystems`
> exposes `MainPass` / `PostProcess` (and, per the migration notes, a possible
> `EarlyPostProcess` split plus a 2D `Prepass`).

| Old (0.18) | New (0.19) | Action |
|---|---|---|
| `impl ViewNode for MyNode { fn run(&self, graph, render_context: &mut RenderContext, item, world) }` + `add_render_graph_node::<ViewNodeRunner<MyNode>>(Core2d, Label)` + `add_render_graph_edges(Core2d, (Node2d::A, Label, Node2d::B))` | **`RenderGraph` API removed.** Passes are **systems**: `fn pass(world: &World, view: ViewQuery<…>, mut ctx: RenderContext)` added via `render_app.add_systems(Core2d, pass.after(a).before(b).in_set(Core2dSystems::MainPass))`. `RenderContext` is a SystemParam, not `&mut`. | Rewrite Buiy's `ViewNode` (`node.rs`) as systems; order with `.before()/.after()` on real fns, not `Node2d::*` labels (PR 22144). |
| `Core2dSystems`/`Core3dSystems` had `PostProcess` | split `EarlyPostProcess`+`PostProcess`; 2D also gains `Prepass` | Re-pick correct set for Buiy's pass (it inserted between `StartMainPassPostProcessing` and `Tonemapping`) (PR 23098). |
| `RenderSystems::ManageViews` | split `CreateViews`/`Specialize`/`PrepareViews` | Move systems to right sub-set (Buiy uses `RenderSystems::Prepare` — verify still present). |
| `MeshPipelineViewLayouts`/`MeshPipeline`/etc. immediate | created in `RenderStartup` | Don't assume before `RenderStartup`. |
| `ViewTarget::out_texture*` → value | → `Option` (None when no output surface) | Short-circuit on `None` (PR 23959); relevant to `view_target.get_color_attachment()` at `node.rs:282`. |
| `PipelineCacheError` | `ShaderCacheError` | Rename if matched (PR 22362). |
| `ShaderStorageBuffer` | `ShaderBuffer` | Rename if used. |
| `bevy_render::define_atomic_id` | `bevy_utils::define_atomic_id` | Update import. |

**The old `bevy_scene` serialization path** was renamed `bevy_scene` →
`bevy_world_serialization` (`Scene` → `WorldAsset`, `DynamicScene` →
`DynamicWorld`, `ScenePlugin` → `WorldSerializationPlugin`, …;
`DynamicWorldBuilder` now takes `&TypeRegistry` explicitly). **The
`bevy_scene`/`bevy::scene` name + `ScenePlugin` now belong to BSN.** Buiy almost
certainly does not touch the old path, but grep examples/tests for
`Scene`/`SceneRoot` to be sure.

**Plugin-defaults note:** `UiWidgetsPlugins`/`InputDispatchPlugin` now in
`DefaultPlugins` (PR 23346) — N/A (Buiy doesn't use `DefaultPlugins`).
`bevy_window`/`bevy_picking` feature-collection reshuffles (PRs 22488, 22933,
22990, 23346): Buiy enables these crates directly, so likely unaffected —
**verify the resolved feature graph** after the bump.

## 4. wgpu 27 → 29 render-pipeline breaking changes

**Scoping discipline (avoids a class of false work):** the wgpu CHANGELOG
`## Unreleased` section is **wgpu 30, NOT 29**. Do **not** apply: optional
vertex-buffer slots, mandatory `@interpolate(flat)`, `Queue::present`,
`dispatch_workgroups` rename, `get_mapped_range -> Result`. 29.0.3 confirmed to
still expose `set_immediates`, `set_scissor_rect`, and
`RenderPassDescriptor.multiview_mask`.

**Masking principle:** Buiy consumes wgpu through bevy_render re-exports and Bevy
wrapper types. Bevy's `RenderPipelineDescriptor` (`layout: Vec<BindGroupLayout>`,
its own `push_constant_ranges`) and `RenderDevice` helpers **absorb** several
wgpu field changes. **First migration step: grep Buiy's render crate for raw
`wgpu::`/`render_resource::` descriptor literals vs. Bevy-wrapper usage** to split
"Buiy must change" from "Bevy absorbs."

## 5. accesskit / winit breaking changes

**Headline: the migration surface is tiny — effectively one struct field.** The

## 6. BSN API reference (the `buiy_bsn` design substrate)

Built from shipped `v0.19.0-rc.3` source (authoritative), PR #23413, docs.rs.

**Naming caveat (load-bearing):** PR-body/blog prose says `GetTemplate` and
`Construct`/`ConstructContext`. **The shipped rc.3 source uses `FromTemplate`
(not `GetTemplate`), and `Construct`/`ConstructContext` do not exist** (superseded
by `Template`/`TemplateContext`). Design `buiy_bsn` against the rc.3 names below.

### Syntax — `bsn! { … }`

`bsn!` expands to a value implementing `Scene`; `bsn_list!` → `SceneList`. Both
re-exported from `bevy_scene` (+ its `prelude`); proc-macros live in
`bevy_scene_macros`.

- **Component patches:** `Transform { translation: Vec3 { y: 4.0 } }` (partial =
  patch; rest from template default; multiple patches of same component
  **merge/layer**). `Node` (bare default). `BackgroundColor(srgb(1,0,0))`
  (tuple-struct). `Emotion::Happy { amount: 10 }` (top-level enum patch = fully
  patchable; nested enum patch requires all fields). `Transform::from_xyz(...)` /
  `Transform::IDENTITY` (constructor/const = **full overwrite**, not patch).
- **Children/relationships:** `Children [ a, b, (CompA CompB) ]` (parens group
  multiple components on one child); `ChildOf(entity)`. Any `RelationshipTarget`
  via `queue_spawn_related_scenes::<T>`.
- **Named entities/refs:** `#Root` inserts `Name("Root")` and registers the entity
  in macro scope; `CurrentButton(#MyButton)` resolves a named entity to `Entity`
  (via `EntityTemplate`/`SceneEntityReference`).
- **Expression escape:** `{ rust_expr }` in field position (implicit `.into()`) or
  scene-entry position (must yield a `Scene`). Inline variables:
  `BackgroundColor(black)`.
- **Inheritance/composition:** `:button` (inherit a cached no-arg scene fn),
  `button("Click Me")` (parameterized, non-cached), `:"button.bsn"` (asset file —
  **loader NOT shipped**, see asset section). Inherited scene = base layer; later
  patches override.
- **Templates:** `@MySceneComp { … }` (SceneComponent, bound to `@` in rc.3
  prelude), `~MyTemplate { value: 10 }` (raw Template by type name),
  `template(|ctx| Ok(...))` (world-aware callback), `template_value(Foo::Bar)`.
- **Observers:** `on(|t: On<Jump>| { … })` (inline entity observer).
- **No control flow** in `bsn!` (no `if`/`match`/loop). Conditionals done in Rust
  by building the `Scene`/`SceneList` value (e.g. `Option<L>: SceneList`, or
  `{ expr }`). Splice a list with `[ { scene_list_value } ]`.
- **`bsn_list! [ … ]`** produces a `SceneList`; all entries share one name scope
  (cross-references resolve → graphs).

### Traits / types

**`Template` / `FromTemplate`** — `bevy_ecs::template` (re-exported by
`bevy_scene`):

```rust
pub trait Template { type Output; fn build_template(&self, ctx: &mut TemplateContext) -> Result<Self::Output>; fn clone_template(&self) -> Self; }
pub trait FromTemplate: Sized { type Template: Template<Output = Self>; }
// blanket:
impl<T: Clone + Default + Unpin> Template     for T { type Output = T; }
impl<T: Clone + Default + Unpin> FromTemplate for T { type Template = T; }
```

`Template` is repeatable (`&self`, non-consuming) + cloneable — that's what lets
one scene spawn many entities.

**`TemplateContext<'a,'w>`** (replaces old `ConstructContext`):
`entity: &mut EntityWorldMut`, `entity_references`. Methods:
`get_entity(SceneEntityReference) -> Entity`, `resource::<R>() -> &R`,
`resource_mut::<R: Resource<Mutability=Mutable>>() -> Mut<R>`,
`resource_entity::<R>() -> Option<Entity>`. `EntityTemplate`
(`Entity | SceneEntityReference | None`) is how `#Name` resolves.

**`Scene` / `SceneList`** — `bevy_scene::scene`.
`Scene::resolve(self, &mut ResolveContext, &mut ResolvedScene)`;
`register_dependencies(&self, &mut SceneDependencies)` declares asset paths to load
before spawning. `SceneList` impl'd by `Vec<S: Scene>`, `Option<L: SceneList>`,
tuples, `bsn_list!`.

**Patch traits** — `bevy_scene`: `PatchTemplate::patch_template`,
`PatchFromTemplate::patch` (what the macro lowers `Comp { field: val }` into).
Component in a patch must satisfy
`T: Template<Output: Component> + Send + Sync + Default + 'static`.

**Spawn entry points** (`bevy_scene::spawn`, all in prelude):

- `WorldSceneExt::spawn_scene<S> -> Result<EntityWorldMut, SpawnSceneError>`;
  `queue_spawn_scene` (waits for deps); `spawn_scene_list`,
  `queue_spawn_scene_list`.
- `CommandsSceneExt::spawn_scene -> EntityCommands` (errors logged);
  `queue_spawn_scene`.
- `EntityWorldMutSceneExt::apply_scene`/`queue_apply_scene`/`queue_spawn_related_scenes::<T>`
  (apply onto existing entity).
- `EntityCommandsSceneExt` → `&mut Self` for chaining.

**No opaque "scene handle"** — you get the spawned root entity
(`EntityWorldMut`/`EntityCommands`/`Entity`). "queued" variants defer spawning
until declared asset deps finish loading.

### Component requirements (the single most important fact for `buiy_bsn`)

**Compile-time via the macro + `Template`/`FromTemplate`. No reflection, no type
registry at spawn.** A component is `bsn!`-authorable if either:

1. **Plain data:** `Component + Clone + Default` (`+ Unpin`, ~always). The blanket
   impl makes it its own template. **Common case:
   `#[derive(Component, Clone, Default)]` and that's it.**
2. **Needs spawn-time context** (asset handles from strings, entity refs, world
   access): `#[derive(Component, FromTemplate)]` — generates e.g.
   `IconTemplate { image: HandleTemplate<Image> }`. Requires **every field to
   implement `FromTemplate`** (or carry `#[template(...)]`). `Handle<T>` has
   `HandleTemplate<T>` turning `"path.png"` into a loaded handle via
   `ctx.resource::<AssetServer>()`.

**Conflict rule:** a type can't both rely on the `Clone+Default` blanket *and*
hand-derive its own template — pick one.

**Reflect / `register_type` NOT required** for `bsn!` authoring or `spawn_scene`.
(Reflection is only for the future editor/inspector and the deferred `.bsn` asset
loader.) **`#[require(...)]` is orthogonal** — honored by BSN spawns exactly as in
normal `spawn`/`insert`; keep using it. Caveat (runtime): component requirements
must be registered before the requiring component is first inserted, or it panics
— register widget components/plugins early in plugin `build`.

### Asset format — `.bsn` loader: **DEFERRED**

PR #23413: *"this does not include a loader for the BSN asset format."* rc.3 docs:
*"not yet implemented."* The `:"file.bsn"` syntax is accepted and
`ScenePatch`/`register_dependencies` plumbing exists, but **there is no
`AssetLoader`** — `:"file.bsn"` has no runtime backing in rc.3. **Target inline
`bsn!` (+ function scenes) only.**

### Feature gate

- Crate is **`bevy_scene`**, enabled by the **`bevy_scene`** cargo feature; the
  `scene` *collection* = `{ bevy_scene, bevy_world_serialization }`. **No separate
  `bsn` feature** in rc.3 — `bsn!`/`bsn_list!` ship inside `bevy_scene`.
- `Template`/`FromTemplate`/`TemplateContext` come from `bevy_ecs`
  (`bevy_ecs::template`), re-exported through `bevy_scene`.
- **Buiy action: add the `bevy_scene` feature** (already done in the worktree).
  `bevy_world_serialization` only needed for ECS (de)serialization, not inline
  `bsn!`. No `bevy_ui`/`bevy_text` pulled. Treat as std (Buiy is a desktop
  wgpu/winit stack).

### Minimal end-to-end example

```rust
use bevy_ecs::prelude::*;
use bevy_scene::prelude::*;   // bsn!, Scene, WorldSceneExt, CommandsSceneExt, ...

#[derive(Component, Default, Clone)]
struct Score(usize);
#[derive(Component, Default, Clone)]
struct Sword;

fn setup(world: &mut World) {
    world.spawn_scene(bsn! {
        #Player            // -> Name("Player")
        Score(0)
        Children [ Sword ]
    }).unwrap();           // Result<EntityWorldMut, SpawnSceneError>
}

fn setup_cmds(mut commands: Commands) {
    commands.spawn_scene(bsn! { #Player Score(0) Children [ Sword ] });  // EntityCommands
}

// context-bearing component (string -> asset handle):
#[derive(Component, FromTemplate)]
struct Icon { image: Handle<Image> }   // generates IconTemplate { image: HandleTemplate<Image> }
// bsn! { Icon { image: "ui/icon.png" } }  -> handle loaded via AssetServer
```

**`buiy_bsn` design takeaways:** authoring is compile-time; the crate is mostly
(a) ergonomic re-exports of `bsn!`/`bsn_list!` + spawn ext traits in a Buiy
prelude, and (b) making Buiy components satisfy `Clone + Default` (blanket
template) or hand a `FromTemplate` for context-bearing fields. Keep `#[require]`
for component deps. Skip `.bsn` files. Use `FromTemplate`/`TemplateContext` names,
pinned to `v0.19.0-rc.3`.
